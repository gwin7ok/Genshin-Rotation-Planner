# フェーズ3 計画: アクション遅延のアクションごとの個別化

関連決定: D6（アクションごとに個別の値を持たせ、gcsim の `delay` で入れる。アプリ側の一律挿入は撤廃）、D19（下記の検討事項の決定）
前提フェーズ: フェーズ2（プリセット削除済み）
後続フェーズ: フェーズ4（各アクションの後に `delay(<フレーム数>)` として出力する）

## 目的

アクション遅延（人の操作の間）を、編成全体で1つの値ではなく、**アクションごと**に設定できるようにする。gcsim 変換時は、各アクションの後に `delay(<フレーム数>)` として出力する（フェーズ4）。

## 現状（着手前）

- `actionDelay`（秒, 既定 0.10）は編成全体で1つの値で、アクションの間（交代の直後の1つ目の前も含む）に一律に挿入されていた。
- 状態: `src/App.tsx`、保存データ、保存スロット、`rotationCalculator.ts` のオプション、`loopBoundary.ts`、`GanttChart.tsx`、`StintSequenceEditor.tsx`、`SaveLoadModal.tsx` に受け渡し。

## gcsim 側の仕様（調査済み）

- `delay(n)`: 直前のアクションが**終わった後**、次のアクションの開始を n フレーム遅らせる。
- `sleep(n)`（旧 `wait`）はアクションのキャンセル可能時点から数えるため、遅延の用途には使わない。

## 決定事項（D19, 2026-09-29）

- **遅延の入る位置**: 全アクションの**終了後**に入れる（gcsim の `delay` と同じ意味）。出場ブロックの最後のアクションの遅延は、次のキャラの交代を遅らせる。交代直後の1つ目のアクションの前の遅延は無くなる（代わりに前のアクションの遅延が入る）。遅延の総数は従来と同じ（各出場でアクション数と同じ）。
- **初期値**: 0.10 秒。`delayAfter` が未設定のアクションはこの値として扱う。
- **旧データの移行**: しない（D13）。旧形式の `actionDelay` は読み込んでも使わない。
- **編集UI**: アクションの後ろに表示する「+0.10s」の ▲▼ で個別に 0.05 秒ずつ変更。上部の一律設定バーは「全アクションに一括設定」ボタン（0 / 0.05 / 0.10 / 0.15 / 0.20 秒）に変えた。
- 交代アクション（自動挿入）は遅延を持たない。交代所要時間（`switchDelay`）は別の設定のまま。

## 作業内容（実施済み）

1. `CharacterActionInstance` に `delayAfter?: number`（秒）を追加。`src/utils/actionDelay.ts` に既定値 `DEFAULT_ACTION_DELAY` と `actionDelayOf` を追加。
2. `rotationCalculator.ts` で、一律の遅延の代わりに、各アクションの終了後に `actionDelayOf(act)` を加える。出場ブロックの終了時刻・全体の時間にも含まれる。
3. 出場ごとの操作画面（`StintSequenceEditor.tsx`）に、アクションごとの遅延の編集と一括設定を追加。
4. 一律の `actionDelay` を、状態・UI・保存項目（現在の編成・保存スロット・JSON）・`loopBoundary.ts`・`GanttChart.tsx` から撤廃。
5. プリセットはフェーズ2で削除済みのため対応なし。

## 完了条件

- アクションごとに遅延を設定でき、ガントチャートの時間に反映される。
- 一律の遅延設定がUI・状態・保存データから無くなっている。
- 型チェック・ビルドが通り、ブラウザで確認済み。

## 影響範囲

- 時間計算、出場ごとの操作画面、保存データ。
- 出場ブロックの最後のアクションの遅延が総時間に入るため、従来の同じ編成より総時間が最大で 0.10 秒×出場数ぶん変わりうる（従来は交代直後の遅延があったため、実際の差は各出場で「最後のアクションの後」と「交代の後」の入れ替わり）。
