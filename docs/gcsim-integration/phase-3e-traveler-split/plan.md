# フェーズ3e 計画: 旅人を空・蛍の別キャラにする（14キャラ）

関連決定: D35（旅人を空・蛍の別キャラにする。「旅人は1人まで」の制約は設けない）、D34（照合表）、D13（IDキーの原則）
前提フェーズ: フェーズ3d（アクションの整理）
後続フェーズ: フェーズ5（照合表。旅人が 1 対 1 で突き合わせられる）

## 目的

現状、旅人は「元素ごとに1キャラ（7キャラ）」で、空と蛍の違いは、性別ごとに動作が違うアクションを `_aether` / `_lumine` の別アクションとして持つことで扱っている。これを、**空と蛍を別のキャラとして、元素ごとに2人（計14キャラ）マスターデータに登録**する。

- genshin-db は空（10000005）と蛍（10000007）を別のキャラ・別のアイコンで持ち、gcsim も `aether<元素>` / `lumine<元素>` の14キーを別々に持つ。マスターデータをそれに合わせる。
- 照合表（D34）が 1 対 1 になり、性別の特別処理が不要になる。空・蛍それぞれの正しいフレーム・アイコン・名前を使える。

## 現状（確認済み: 2026-09-29）

- 旅人は 7 キャラ（ID `10000005-<元素>`、名前「旅人(風)」など、アイコンは空の画像だけ）。
- 空・蛍で違うアクションは、`_aether` / `_lumine` 付きの別アクション（元素ごとに 4〜12 個、合計 54 個）。
- genshin-db: 空 (10000005)・蛍 (10000007) は別のキャラ、アイコンも別（`UI_AvatarIcon_PlayerBoy` / `PlayerGirl`）。天賦・命ノ星座は元素ごと（名前「旅人 (風元素)」）で、空・蛍で共通。
- gcsim: 14キー（`aetheranemo`〜`aetherpyro`、`lumineanemo`〜`luminepyro`）。日本語名は「空 (風元素)」「蛍 (風元素)」。

## 決定事項（D35, 2026-09-29）

- 旅人を、空・蛍の別キャラとして、元素ごとに2人（計14キャラ）で登録する。
- **「旅人は1人まで」の制約は設けない**（編成画面での制限なし）。今も元素違いの旅人を同時に編成できる状態で、変更しない。

## 設計

### ID・名前・アイコン
- ID: 空 `10000005-<元素>`（今の ID のまま）、蛍 `10000007-<元素>`（新規）。`characterKey(公式ID, 元素)` の形を維持する。
- 名前: 「空(風)」「蛍(風)」など。検索用に別名（`englishName` に "Traveler" など）を持たせ、「旅人」で検索しても見つかるようにする。
- アイコン: genshin-db の `filename_icon`（空 `PlayerBoy`、蛍 `PlayerGirl`）から、enka の画像 URL を作る。
- `source.genshinId`: 空 10000005、蛍 10000007。`source.gcsimKey`: `aether<元素>` / `lumine<元素>`。

### マスターデータ生成（`characterMasterGenerator.ts`）
- 旅人を、元素ごとに空・蛍の2ユニットとして生成する。各ユニットは、gcsim のフレームを、性別の添字で切り出した見え方（既存の `genderView`）から作る。
- 天賦・命ノ星座は、元素ごとに同じ内容を空・蛍の両方に複写する（共有元から複写するので、管理は増えない）。
- **性別ごとのアクション統合（`mergeGenderActions`）と `_aether` / `_lumine` のアクション ID は廃止**する。アクション ID は、各キャラで通常の形（`10000005-hydro_e` など）になる。
- 生成器・辞書のうち、キャラ ID をキーにしているもの（別ボタンに残す旅人(水)の `shortHold` 系 `PARAMETER_DERIVED_SKILLS`、凸の効果時間の延長規則、gcsim 変換の対応表など）は、空・蛍の両方の ID を持つ。

### gcsim 変換・その他
- `actionMapping.ts` の性別サフィックス除去（`_(aether|lumine)$`）を削除する。対応表（`CHARACTER_ACTION_OVERRIDES`）に、蛍の ID のぶん（`10000007-hydro_e_shorthold` など）を追加する。
- 照合表（フェーズ5）は、旅人も 14 キー 1 対 1 で生成できる（手で補う必要がなくなる）。

### 保存データ・DB
- 空の ID は変わらない。蛍は新しい ID なので、既存の保存データには影響しない。
- `_aether` / `_lumine` 付きのアクション ID は使えなくなる。旧データの移行はしない（D13）。
- DB のバージョンを上げ、マスターと入れ替える。ロック中の旅人は、旧アクション ID のまま残る。

## 作業内容

1. 生成器を、旅人を空・蛍の別ユニット（14キャラ）にする形に変更し、性別ごとのアクション統合を撤去する。
2. キャラ ID をキーにする生成器・辞書・対応表に、蛍の ID を追加する。
3. `actionMapping.ts` の性別サフィックス除去を削除し、蛍の対応を追加する。
4. 名前（空・蛍）・アイコン・検索用の別名を設定する。
5. マスターデータを再生成し（`npm run build:master`）、DB バージョンを上げる。
6. 型チェック・ビルド、ブラウザで確認（キャラ選択画面に空・蛍が元素ごとに並ぶ、アイコン・名前、旅人(水)の `shortHold` 系ボタン、設定文の変換と `/validate`）。

## 完了条件

- キャラ一覧に、旅人が空・蛍で元素ごとに2人（計14人）出る。名前・アイコンが正しく、「旅人」で検索できる。
- `_aether` / `_lumine` の付いたアクションが無い。空・蛍それぞれが自分のフレームを持つ。
- gcsim 変換が、空・蛍の両方で通る（`/validate`）。
- 型チェック・ビルドが通り、ブラウザで確認済み。

## 影響範囲

- マスターデータの生成と内容、キャラ選択画面、gcsim 変換の対応表、旅人のアクション ID。
- 既存の保存データで、旅人の性別付きアクション ID を使っているものは読み込めなくなる部分がある（D13）。
