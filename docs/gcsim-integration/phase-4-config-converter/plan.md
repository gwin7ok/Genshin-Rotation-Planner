# フェーズ4 計画: 編成 → gcsim 設定文の変換

関連決定: D2〜D8
前提フェーズ: フェーズ1, 2, 3, 3b, 3c

## 目的

アプリの編成（キャラ・装備・出場・アクション・ループ開始点）から、gcsim の設定文を作る変換処理を作る。gcsim のローカルサーバーの `/validate` で文法チェックできるようにする。

## 出力する設定文の構成

```
# キャラごと（D2: レベル・天賦は固定、ステータスは仮値）
<key> char lvl=90/90 cons=<凸数> talent=<固定値>;
<key> add weapon="<武器 gcsimKey>" refine=<精錬> lvl=90/90;
<key> add set="<聖遺物 gcsimKey>" count=4;          # 2+2 のときは出力しない（D5）
<key> add stats <仮ステータス> cr=1;                  # 会心率100%（D2）

# 全体
options iteration=1 duration=<秒> swap_delay=<交代遅延フレーム> ignore_burst_energy=true;   # hitlag は既定(true)のまま（D4）
target lvl=100 resist=0.1;                           # hp は指定しない（撃破モードになるため）
active <最初の出場キャラ>;

# ローテーション
<初動部分: ループ開始点より前の出場>
while 1 {
  <繰り返し部分: ループ開始点以降の出場>
}
```

- キャラの gcsim キー: `CharacterConfig` の元データの `source.gcsimKey`
- 凸数: フェーズ3bの `CharacterModel` の凸数（編成で未設定なら既定値 星4=6・星5=0）を `cons=` に使う
- 武器・聖遺物の gcsim キー: フェーズ1の `gcsimKey`（フェーズ2で ID 参照になった装備から引く）
- アクション遅延: 各アクションの後に `delay(<delayAfter × 60 を丸めたフレーム数>);`（D6）。0 のときは出力しない。
- 交代: gcsim は別キャラのアクションで自動的に交代する。アプリの明示的な交代アクションの扱いは作業時に決める。

## アクションの変換規則（O4: 詳細は作業時に確定）

| アプリの `ActionType` | gcsim の命令（案） |
|---|---|
| `normal` | `attack`（段数に応じて `attack:<n>`） |
| `combo`（例: N3C） | `attack:3, charge` のように分解 |
| `charged` | `charge`（弓の狙い撃ちは `aim`） |
| `plunge` | `low_plunge` / `high_plunge`（どちらかに固定） |
| `skill` | `skill` |
| `skill_hold` | `skill[hold=1]`（多段階の長押しはキャラごとの指定が必要） |
| `skill_reset` | `skill`（リセットの成否は gcsim の乱数。D7 の種の探索はフェーズ6） |
| `burst` | `burst` |
| `dash` / `jump` | `dash` / `jump` |
| `swap` | 次のキャラの命令で自動交代（要確認） |
| `wait` | `delay(<フレーム数>)` |

## シミュレーション時間とループ（O5: 方向性は決定、周数などの詳細は作業時に確定）

- ループ部分は回数指定の `while` で囲み、各周の頭に `print("loop ", i)` を入れて周の区切りをログに残す（全体計画 3.5 の検証結果）。
- 周の回数は**2周以上**にする。「ループ1周目のCTが2周目に間に合わない」CT待ち（D21）を検出するため。CT待ちが無ければ全周の結果が一致するので、書き戻しは1周目の値でよい。何周にするかは作業時に決める（CT待ちが無ければ全周同じ時間になることは確認済み）。
- `duration` は、指定した周数を回り切れる長さにする。CT待ちで周が延びても足りるよう余裕を持たせ、回り切れなかった場合は検出できるようにする。
- 繰り返し部分で CT 待ちが発生すると gcsim はその場で待つ。アプリはこれを違反として示す（D12、フェーズ6）。

## gcsim 未対応の検出

変換前に次を検出し、変換結果と一緒に警告として返す（gcsim 実行はしない）。

- `source.gcsimKey` の無いキャラ（カスタムキャラ・gcsim 未実装キャラ）
- `gcsimKey` の無い武器・聖遺物（カスタム・gcsim 未実装・未設定）
- 変換規則の無いアクション

## 作業内容

1. 変換処理を純粋関数として作る（例: `src/utils/gcsim/buildGcsimConfig.ts`、入力: キャラ・出場・ループ開始点・交代遅延、出力: 設定文と警告）。
2. アクションの変換規則（O4）を確定して実装する。
3. `duration` とループの書き方（O5）を確定して実装する。
4. 既存プリセット全件と、ナヒーダ・ニィロウ・コロンビーナ・ラウマの編成を変換し、gcsim サーバーの `/validate` で文法エラーが無いことを確認する。
5. 開発中の確認用に、設定文を表示・コピーできる手段を用意するかを判断する。

## 完了条件

- 対応キャラのみで構成された編成が、エラーなく gcsim の設定文に変換され、`/validate` を通る。
- 未対応要素を含む編成では、何が未対応かが警告として分かる。

## 影響範囲

- 新規処理の追加のみ（既存機能への影響なし）。
