# フェーズ5 計画: gcsim キーの辞書の生成

関連決定: D33（genshin-db 主体＋gcsim 補完）、D34（DBキーの照合表）、D10（分類の判定方法 A: gcsim ソースから自動生成＋手で補う一覧）、D11（表示の分類。バーのデータの共通の型は D20 で取り下げ）、D20（辞書は、gcsim のバフ付与イベントを固有天賦・武器・聖遺物の発動バフの定義に対応付けるために使う）
前提フェーズ: なし（フェーズ1〜4と並行可能。フェーズ6の前に必要）

## 目的

gcsim の詳細ログに出てくるバフ・状態・内部CTのキー名（例: `khaj-nisut-team-buff`, `tom-4pc-icd`, `lauma-c1`）から、ガントチャートに必要な情報を引ける**キーの辞書**を作る。

| 辞書で引く情報 | 内容 |
|---|---|
| 分類 | スキル / 爆発 / 固有天賦 / 命ノ星座 / 武器 / 聖遺物 / その他（元素共鳴・システム・敵デバフ） |
| 種類 | 効果 / CT（ユーザーに見せる発動制限） / 内部（見せない: ダメージ・粒子の内部クールダウンなど） |
| 発動元 | キャラ（gcsim キャラキー）/ 武器 / 聖遺物セット |
| 紐付け | CT がどの効果のものか（例: `khaj-nisut-icd` → `khaj-nisut-buff`） |
| 表示名 | 日本語の表示名（手で補う） |

## 背景（分析結果 2026-09-28）

- gcsim のログで分類が明確なのは、スキル・爆発のCT（`cooldown` イベント）だけ。
- バフ・状態は `status` イベントの mod / status として、分類を示す項目なしに同じ形で出る。キー名の付け方は統一されていない（`nahida-q-within` はキャラ名付き、`pirouette`・`lunarprayer` は付かない）ため、名前の規則では判定できない。
- 固有天賦・武器・聖遺物のCTは専用イベントがなく、`〜-icd`・`〜-cd` のステータスとして出る。見せたいCTと内部クールダウンが混ざる。
- 4分類に収まらないもの: 命ノ星座（`lauma-c1`）、元素共鳴（`dendro-res-30`, `hydro-res-hpp`）、システム効果（`ascendant-gleam`）、敵デバフ（深林4の耐性ダウンなど）、常時効果（`expiry=-1`）。
- キー名が**定義されている gcsim のソースの場所**で、分類はほぼ機械的に決まる:

| キー名 | 定義場所 | 分類 |
|---|---|---|
| `khaj-nisut-team-buff` | `internal/weapons/sword/keyofkhajnisut/` | 武器 |
| `tom-4pc-icd` | `internal/artifacts/tenacity/` | 聖遺物（CT） |
| `lauma-c1` | `internal/characters/lauma/cons.go` | 命ノ星座 |
| `nahida-q-within` | `internal/characters/nahida/burst.go` | 爆発 |
| `dendro-res-30`, `ascendant-gleam` | `pkg/simulation/setup.go` | 元素共鳴・システム |
| `pirouette` | `internal/characters/nilou/` の複数ファイル | 定義元の判定が必要 |

## 作り方（D10）

1. **自動生成（ビルド時スクリプト）**: gcsim のソースを取得し、キーを登録している呼び出し（`AddStatus` / `AddStatMod` / `AddAttackMod` / `AddReactBonusMod` / `AddResistMod` などの mod・status 登録、および定数定義）からキー名を抽出する。
   - 定義場所から分類・発動元を決める:
     - `internal/characters/<key>/skill.go` → スキル、`burst.go` → 爆発、`asc.go` → 固有天賦、`cons.go` → 命ノ星座
     - `internal/weapons/**/<weapon>/` → 武器、`internal/artifacts/<set>/` → 聖遺物
     - `pkg/simulation/setup.go` など → その他（元素共鳴・システム）
   - キー名や変数名の `icd` / `cd` からCT・内部の候補を判定する。
   - 既存の gcsim ソース解析（`src/masterdata/gcsimParser.ts`、キャラ生成の gcsim 取得処理）の仕組みを流用する。
2. **手で補う一覧（上書き）**: 自動で決まらないもの（複数ファイルにまたがるキー、CTと効果の紐付け、見せたいCTか内部か）と日本語の表示名を、手で管理する一覧で上書きする。
3. **レポート**: 自動判定できなかったキー・上書きの無い未分類キーを一覧で出す（新キャラ追加時に確認できるように）。
4. 生成物をアプリに同梱する（例: `src/data/gcsim_key_catalog.json`）。対応する gcsim のバージョン（コミット）を記録する。

## 発動バフのボタンとの関係（D28）

比較調査（`survey-buff-comparison.md`）を受けて、辞書は次の用途にも使う。

- **発動バフのボタンの候補**: gcsim のキーから、キャラごとの発動バフの候補（固有天賦・武器・聖遺物・命ノ星座）を作る。対象は、**時間付きの効果だけ**（常時効果は表示しない）。命ノ星座は、凸数が足りているときだけ出す。
- **「gcsim 対象外」の判定**: アプリのボタンのうち、辞書に対応するキーが無いもの（アプリのみ）に、UI で「gcsim 対象外」の印を付けるための根拠にする。
- **決定済み**: O8 は D38（複数キーは別のバー、同じ効果は順番で対応付け、置き場所は直前の出場ブロック）。常時効果は、D38 で全体の行にボタンとして表示する（D28-2 を置き換え）。
- **決定済み**: O9 は D41（gcsim キー無しの9キャラのボタンは手動で残し「gcsim 対象外」の印）と D40-4。
- **（旧）実装前に決めること**: O9（gcsim キー無しのキャラのボタン・時間の無いボタンの扱い）。辞書の作り方・使い方に関わるため、フェーズ5の実装前に決める。
- **対応付けの限界**: 共有パッケージ（`weapons/common`: 黒岩・金璋君臨など）は、個別の武器に対応付ける必要がある。調査では、キーが動的に作られるもの 78 件、持続が式で解決できないもの 145 件が未解決だった。

## 決定事項（D33・D34, 2026-09-29）

- **生成方針（D33）**: マスターデータは genshin-db 主体で生成し、gcsim は補完に使う。genshin-db に無い設定値（効果時間・CT・状態など）を、gcsim で可能な限りカバーする。
- **突き合わせ（D34）**: genshin-db と gcsim の突き合わせに、名前は使わない。**DBキーの照合表**（genshin-db の公式 ID ↔ gcsim のキー）を**あらかじめ作成して保持**し、生成時はそれを引く。

## 照合表の構成（2026-09-29 の調査を踏まえた案）

| 階層 | 内容 | 作り方 |
|---|---|---|
| 1. レコード | キャラ・武器・聖遺物の公式 ID ↔ gcsim キー | gcsim の `ui/packages/ui/src/data/{character,weapon,artifact}.dm.json`（公式 ID と key を持つ）から自動生成。旅人（空・蛍）・共有パッケージ（`weapons/common`: 黒岩・金璋君臨など）は手で補う |
| 2. 効果 | 発動バフの定義 ID（固有天賦 `_p1` / `_p2`、武器 `wbuff_`、聖遺物 `abuff_`、命ノ星座）↔ gcsim の効果キー（`AddStatus` / `modifier.NewBase` のキー） | gcsim ソースから自動抽出し、手で補う一覧で上書き（D10 のキーの辞書） |
| 3. アクション | スキル・爆発の効果時間・CT ↔ gcsim の効果キー・`SetCD` | 同上 |

- 現状の突き合わせは、すでに公式 ID ベース（キャラ・武器・聖遺物）。照合表として保持することで、(a) 一覧で確認できる (b) 突き合わせに失敗したもの・手で補ったものが分かる (c) 生成のたびにネットから再計算しなくてよい、を狙う。
- 調査結果（2026-09-29）: キャラは公式 ID で 112 件一致、genshin-db のみ 9 件（gcsim 未対応）、gcsim のみは蛍のキー 7 件（旅人）。武器は 234 件一致、genshin-db のみ 11、gcsim のみ 10（星1〜2の初期武器）。聖遺物は 55 件一致、genshin-db のみ 8。武器・聖遺物のキーは、現在のマスターとの不一致が 0 件。
- 照合表に載らない（gcsim 未対応の）レコードは、「gcsim 対象外」として一覧に残す（D28-3）。

## gcsim での補完の対象（D33・調査結果）

- **効果時間**（スキル・爆発）: genshin-db にラベルが無い、または読み取れないもの。フィッシュルの Q（Oz 10秒、6凸 12秒。genshin-db に時間のラベルが無い）、フィッシュル E（「オズの存在時間」を読めていない）のような例。gcsim にだけある効果時間は 19 件（フレミネ E の加圧 10秒、煙緋 E の印 10秒、ムアラニ E の印 10秒 など）。genshin-db のラベルの読み落とし（存在時間・長押し最大継続時間・石化時間 など約10件）は、読み取りの規則の拡張でも直す。
- **CT**: genshin-db と 210 件が一致、9 件が不一致（状態で変わる値、丸め）。genshin-db を主として、取れないもの・状態依存を gcsim で補う。
- **発動バフ**: D28（時間付きの効果をボタンにする）の候補を、gcsim のキーから作る。
- **名前**: gcsim の `names.dm.json`（日本語名）は、照合表で突き合わせた後の名前のずれの検出に使える（任意。マスターの名前とは、キャラ 111/111、武器 234/234、聖遺物 55/55 が一致）。
- 補完の値は、出典（gcsim のキー・ファイル）を記録し、genshin-db の値と区別できるようにする。gcsim 由来の値が genshin-db の値と食い違う場合は、genshin-db を優先し、レポートに出す。

## 作業内容

1. gcsim ソースからキーを抽出する方法を実装で確認する（mod・status の登録関数の種類、キーが定数や変数で渡される場合の解決）。
2. 自動生成スクリプトとレポートを作る。
3. 手で補う一覧の形式を決め、対象4キャラ（ナヒーダ・ニィロウ・コロンビーナ・ラウマ）と、その編成で使う武器・聖遺物の分を先に埋める。
4. 前回の検証ログ（テスト編成の Sample）に出た全キーが辞書で引けることを確認する。

5. 照合表（レコード）を、`dm.json` から自動生成して保存する（例: `src/data/gcsim_key_map.json`。手で補う一覧を別ファイルに持つ）。マスターデータ生成（キャラ・武器・聖遺物）を、この表を引く形にする。
6. マスターデータの補完: 効果時間・CT の gcsim による補完（genshin-db に無い・読み取れないもの）と、genshin-db のラベルの読み取り規則の拡張を実装する。レポートに補完した件数と一覧を出す。

## 完了条件

- 照合表があり、生成時に名前ではなく照合表で突き合わせている。突き合わせできなかったものが一覧で分かる。
- フィッシュルの Q・E など、genshin-db で 0 秒になっていた効果時間が、gcsim の補完で入る（出典が記録される）。

- テスト編成の Sample に出た全キーが、分類・種類・発動元つきで辞書から引ける（または「内部」として除外される）。
- 自動判定できなかったキーがレポートで分かる。

## 影響範囲

- 新規のビルドスクリプトとデータファイルの追加のみ（既存機能への影響なし）。

## CTの開始位置の補完（D37）

- マスターの各スキル・爆発のアクションに、「CT開始位置」（`{基準: 動作開始 | 長押し終了, 遅れ: 秒}`）を持たせる。スキルと爆発は同じ項目・同じ計算にして、構造をシンプルにする。
- 生成: gcsim の `skill.go` / `burst.go` の `SetCD` / `SetCDWithDelay` の遅れフレームを読み取る。調査（118キャラ）では、動作開始と同時が 24、遅れありが 92（約3分の1は変数・配列）、長押し終了が十数キャラ。読めないもの・ホールド依存のもの・CTの長さが変わるもの（早柚・綺良々・ナヒーダ・アンバー・状態依存の蒸気系）は、辞書で補う。
- 「効果時間の終了で開始」の基準は作らない（該当なし。見つかったら追加）。
- 長押しで CT の長さが変わるキャラは、CT の長さもホールド秒数の関数として持つ。
- 旅人(水)のホールド系は、D36 で CT を設定済み。開始位置は 371f（最大ホールド）・56f（short）・11f（0Ticks）、一回押しは 24f。

## 分類の既定（D40）

- 辞書に、効果ごとの分類（常時 / 条件付き / gcsim が発動位置を計算する）を持たせる。既定は「条件付き」。辞書で「常時」と確認できたものだけ「常時」にする。「gcsim が発動位置を計算する」は、辞書に時間付きのキーがあるもの。
- 時間の無い固有天賦のボタン（149個）は、出場キャラのトラックのボタンから取り除き、全体の行だけに出す。
