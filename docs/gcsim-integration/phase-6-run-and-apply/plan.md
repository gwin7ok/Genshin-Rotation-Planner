# フェーズ6 計画: gcsim 実行と結果の書き戻し

関連決定: D1, D7, D10, D20（書き戻し方式）, D21（CT待ちの扱い）。D11・D12 は D20・D21 で置き換え
前提フェーズ: フェーズ4（設定文の変換）、フェーズ5（キーの辞書）

## 目的

ボタン1つで、編成を gcsim で実行し、結果（アクション・CT・効果の時刻）を、**ユーザーが編集できる値に書き戻す**。ガントチャートは従来どおり、これらの値からアプリの計算で作る。書き戻した後も、ユーザーは同じ値をこれまでどおり編集できる。

## 書き戻しの対応（D20）

| 書き戻し先（ユーザーが編集できる値） | gcsim のログからの求め方 |
|---|---|
| アクションの所要時間 `duration` | `action` イベントの開始時刻の差（キャンセル反映済みの実時間）。交代と遅延を除いた分 |
| アクション遅延 `delayAfter` | アクション開始時刻の差から所要時間を引いた残り（フェーズ4で入れた `delay` に一致するはず） |
| スキル・爆発の CT `cooldown` | `cooldown` イベント（`triggered` 〜 `ready`、短縮・リセットを反映） |
| スキル・爆発の効果時間 `effectDuration` | `status` イベントの開始 〜 `ended` |
| 発動バフ（固有天賦・武器・聖遺物）の位置 `offset` | バフ付与イベント（`mod added` など）の発生時刻から、その出場の先頭からの秒数を逆算 |
| 発動バフの継続時間 `duration`・CT `cooldown` | `status` イベントの開始 〜 `ended`、内部CTのイベント |

- ユーザーが手で入れた値は、上書きで失われる（D20）。書き戻した後の値は、これまでどおり編集できる。編集した値を自動値に戻したいときは、gcsim の計算を再実行して全体を上書きする（D32。個別の「自動に戻す」ボタンは作らない）。
- **発動バフの反映ルール（D29）**:
  - ユーザーがすでに追加している要素（固有天賦・武器・聖遺物・命ノ星座の発動バフ）は、gcsim の結果の**発動位置・効果持続時間・CT で上書き**する。
  - 追加していない要素は、gcsim の結果に出ていれば、**アプリが追加してから各設定値を上書き**する。
  - この2つで、(a) 入力に必要なアクションだけを入れて、他の要素は結果から自動追加する使い方と、(b) 入力に不要な要素もある程度追加してガントチャートで状況を見てから gcsim で計算する使い方の、**両方に対応**する。
- **gcsim に無い効果（D28-3）**: gcsim の結果に出ない固有天賦・武器効果（アプリのみのボタン）は、上書き対象外でそのまま残る。UI に「gcsim 対象外」の印を付ける。
- **表示する範囲（D28）**: 時間付きの効果（命ノ星座を含む。凸数が足りているときだけ）を対象にする。常時効果（永続）は表示しない。
- 交代所要時間 `switchDelay` の扱い（`swap_delay` で渡した値がそのまま結果に出る）は作業時に確認する。

## CT待ちの扱い（D21）

> 背景（全体計画 3.6）: アプリの秒数は固定のフレーム値のため、gcsim の実際の時間（キャンセル・状態依存）と乖離し、アプリでは違反なしでも gcsim でCT待ちになる編成がある。
> ポップアップにはアプリ自身のCT違反を表示済み（D24）。

CT待ちが生じるケースは、結果の反映を保留する。

1. **ボタン押下時**: アプリの既存のCT違反検出に違反がある場合は、解消を促すプロンプトを出し、gcsim を実行しない。
2. **計算前に違反が無かった場合**: gcsim の実行後、結果にCT待ち（`event=sim` の `could not execute <action>; action not ready`）があれば、書き戻さない。CT待ちが生じたアクションに、既存と同じ形の違反マークを付ける（残りCTは gcsim の実際の待ち時間）。
3. この仕様により、ループ部分のCTが間に合わない周が無くなるため、1周目と2周目以降で結果が異なることは起きない。書き戻しは1周目（初動＋ループ1周目）の値でよい。周ごとの結果の一致は、CT待ちが無ければ確認済み（全体計画 3.5）。

## 作業内容

### 6-1. gcsim クライアント

- ※ `/validate` の呼び出し（`src/utils/gcsim/gcsimClient.ts`）はフェーズ4で実装済み（D23）。ここでは `/sample` を追加し、未起動・タイムアウトの扱いを共通化する。

- `POST http://localhost:54321/sample/{id}` に `{config, seed}` を送り、詳細ログを受け取る処理。
- サーバー未起動・タイムアウト・設定文エラーの扱い（起動手順の案内を表示）。
- 必要に応じて `/validate` を事前に呼ぶ。

### 6-2. ログの読み取り

フレーム（60fps）を秒に変換し、次のイベントを読み取る（イベント仕様は [全体計画 3.2](../plan.md#32-詳細ログsampleの内容) を参照）。

| 読み取るもの | 元のイベント |
|---|---|
| アクションの開始 | `action` の `executed <action>`。終了 = 次のアクションの開始 |
| 出場（stint）の区切り | `executed swap` |
| スキルCT・爆発CT | `cooldown` の `triggered` 〜 `ready`（`forcefully reset/reduced/discarded` を反映） |
| 効果・固有天賦/武器/聖遺物のCT | `status` の `mod added/refreshed/extended` と `status added`（開始 `frame`、終了 `ended`）。どの発動バフの定義に対応するかは**キーの辞書**で引く |
| CT待ち | `event=sim` の `could not execute ...; action not ready` |

- 除外: 辞書で「内部」とされたキー。辞書に無いキーは除外し、開発時に分かるよう一覧で記録する。
- チームバフは受け取るキャラごとに記録されるので、発動元キャラにまとめる（同じキーの重複を1本にする）。
- 読み取り処理は1か所にまとめ、未知のイベントは無視する（gcsim の更新対策）。対応した gcsim のバージョンを記録する。

### 6-3. 書き戻し

- gcsim のアクション列を、アプリの出場・アクションの並びに順番で対応付け、上の表に従って値を書き戻す。
- 書き戻し前後の値の差を、利用者が確認できるようにするか（元に戻す操作を用意するか）は作業時に判断する。

### 6-3b. CT待ちの検出と違反マーク（D21）

- ボタン押下時の既存のCT違反の検出とプロンプト。
- gcsim の結果のCT待ちを検出し、書き戻さずに、該当アクションに違反マークを付ける。
- 「CT待ちがあるため結果を反映していない」ことが分かる表示を出す。

### 6-4. 祭礼リセットの乱数の種の探索（D7）

- アプリで `skill_reset`（祭礼リセット）を指定した箇所で、実際に gcsim のログに `sacrificial proc'd` とCTリセットが起きている種を探す。
- 種を変えて `/sample` を繰り返し、条件を満たした最初の種を採用する。回数には上限を設け、見つからなければ警告を出して最も近い結果を使う。
- 採用した種は結果と一緒に保持する（同じ編成で再現できるように）。

### 6-5. UI

- 「gcsim で計算」ボタン、実行中表示、エラー・警告表示（未対応要素、CT違反による中止、種が見つからない等）。
- 書き戻し後は、これまでの編集UIでそのまま値を編集できる。

## 完了条件

- ナヒーダ・ニィロウ・コロンビーナ・ラウマの編成で、ボタンから gcsim を実行し、アクションの所要時間・遅延・CT・効果時間・発動バフの位置が書き戻され、ガントチャートが更新される。書き戻し後の値を編集できる。
- 祭礼リセットを含む編成で、指定どおりにリセットされる種が採用される（見つからない場合は警告）。
- 計算前にCT違反がある編成では、解消を促すプロンプトが出て計算されない。計算前に違反が無く、gcsim の結果でCT待ちが生じる編成では、書き戻されずに違反マークが付く。
- サーバー未起動時に案内が出る。
- 型チェック・ビルドが通り、ブラウザで確認済み。

## 影響範囲

- 編集できる値（`CharacterActionInstance` / `PassiveTriggerInstance` など）への書き込み処理の追加。
- ガントチャートの表示・時間計算は基本的に従来のまま（バーのデータの新しい共通の型は作らない）。
