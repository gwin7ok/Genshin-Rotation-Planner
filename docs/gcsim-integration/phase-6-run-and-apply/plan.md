# フェーズ6 計画: gcsim 実行と結果のガントチャート反映

関連決定: D1, D7, D10, D11
前提フェーズ: フェーズ4（設定文の変換）、フェーズ5（キーの辞書）

## 目的

ボタン1つで、編成を gcsim で実行し、結果（アクション・CT・効果の時刻）をガントチャートに配置する。

## 開始前に決めること（未決事項）

- **O1**: 手動のCT・効果時間の上書き、発動バフのドラッグ配置を、gcsim 実行時にどう扱うか（無効化・参考表示など）。gcsim 入力には渡す手段がない（分析結果 2026-09-28）。
- **O2**: 表示する分類の範囲。「その他」（元素共鳴・システム・敵デバフ）と常時効果（`expiry=-1`）を表示するか。
- **O3**: 従来の自前計算を残すか（gcsim 未実行時・未対応キャラを含む編成の表示）。

## バーのデータの持ち方（D11）

gcsim の結果から、分類によらない**共通の1つの型**でバーのデータを作る（型名は作業時に決める）。

| 項目 | 内容 |
|---|---|
| 分類 | スキル / 爆発 / 固有天賦 / 命ノ星座 / 武器 / 聖遺物 / その他 |
| 種類 | 効果 / CT |
| キー名 | gcsim のキー名（キーの辞書の見出し） |
| 発動元キャラ | バーを表示するキャラ（チームバフは受け取り側ではなく発動元の行に出す） |
| 開始・終了 | 秒（フレーム ÷ 60） |
| 表示名 | キーの辞書の日本語名 |

- 現状の分類ごとの型（`CooldownSpan` / `ActiveBuffSpan` / `PassiveSpan`）から移行する。O3 の決定（従来計算を残すか）に合わせて、既存の型との関係を決める。
- 表示の分類は現状の4分類（スキル・爆発 / 固有天賦 / 武器 / 聖遺物）を残し、命ノ星座とその他を追加する。

## 作業内容

### 6-1. gcsim クライアント

- `POST http://localhost:54321/sample/{id}` に `{config, seed}` を送り、詳細ログを受け取る処理。
- サーバー未起動・タイムアウト・設定文エラーの扱い（起動手順の案内を表示）。
- 必要に応じて `/validate` を事前に呼ぶ。

### 6-2. ログの読み取り（ログ → 共通のバーのデータ）

フレーム（60fps）を秒に変換し、次のように組み立てる（イベント仕様は [全体計画 3.2](../plan.md#32-詳細ログsampleの内容) を参照）。

| 作るもの | 元のイベント |
|---|---|
| アクションの開始・終了 | `action` の `executed <action>`。終了 = 次のアクションの開始 |
| 出場（stint）の区切り | `executed swap` |
| スキルCT・爆発CT | `cooldown` の `triggered` 〜 `ready`（`forcefully reset/reduced/discarded` を反映） |
| 効果・固有天賦/武器/聖遺物のCT | `status` の `mod added/refreshed/extended` と `status added`（開始 `frame`、終了 `ended`）。分類・種類・発動元・紐付けは**キーの辞書**で引く |

- 除外: `event=sim` の `could not execute ...`、辞書で「内部」とされたキー、O2 で表示しないと決めた分類。
- チームバフは受け取るキャラごとに記録されるので、発動元キャラの行にまとめる（同じキーの重複を1本にする）。
- 辞書に無いキーは除外し、開発時に分かるよう一覧で記録する。
- 読み取り処理は1か所にまとめ、未知のイベントは無視する（gcsim の更新対策）。対応した gcsim のバージョンを記録する。

### 6-3. アプリのアクションとの対応付け

- gcsim のアクション列を、アプリの出場・アクションの並びに順番で対応付ける（各アクションの開始・終了時刻をアプリのアクションに反映）。
- ループの1周目・2周目の区切り（繰り返し部分の開始）を求め、既存の2周目表示（持ち越し）に対応させる。

### 6-4. 祭礼リセットの乱数の種の探索（D7）

- アプリで `skill_reset`（祭礼リセット）を指定した箇所で、実際に gcsim のログに `sacrificial proc'd` とCTリセットが起きている種を探す。
- 種を変えて `/sample` を繰り返し、条件を満たした最初の種を採用する。回数には上限を設け、見つからなければ警告を出して最も近い結果を使う。
- 採用した種は結果と一緒に保持する（同じ編成で再現できるように）。

### 6-5. UI

- 「gcsim で計算」ボタン、実行中表示、エラー・警告表示（未対応要素、種が見つからない等）。
- 結果をガントチャートに反映。分類ごとの表示（色・バッジ）に命ノ星座とその他を追加。O1〜O3 の決定に従う。

## 完了条件

- ナヒーダ・ニィロウ・コロンビーナ・ラウマの編成で、ボタンから gcsim を実行し、アクション・CT・効果が分類ごとにチャートに配置される。
- 祭礼リセットを含む編成で、指定どおりにリセットされる種が採用される（見つからない場合は警告）。
- サーバー未起動時に案内が出る。
- 型チェック・ビルドが通り、ブラウザで確認済み。

## 影響範囲

- ガントチャートの表示、バーのデータの型、時間計算の流れ（O3 の決定次第で大きく変わる）。
