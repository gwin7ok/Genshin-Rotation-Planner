# スキルストック数の行（実装計画）

作成: 2026-10-09。ユーザー依頼。**実装済み（2026-10-09）**。ユーザー決定: 推奨どおり（満タンのバーは時間 0 から（ユーザー指示で変更。出場に関わらず）・ファルカ等の特殊スキルは対象外）。ただし**凸で回数が増えるキャラも対象**（夜蘭・スクロース・甘雨・申鶴など。`CharacterModel.actions` が凸を反映済み）、持ち越しは点線ではなく、**1 周目・2 周目で 1 行ずつ**（2 周目の行は、ループ先頭から、1 周目の終わりの状態から続けて表示）。実装: `CooldownQueue` の `onSize` コールバック・`rotationCalculator.ts` の `StockLog`/`buildStockSpans`・`CalculatedRotation.stockSpans`・`GanttChart.tsx` の「スキルストック」行。確認: tsc・check:snapshots（73 並び。`stock` が増える 22 並びだけ差。他の項目は不変）。画面確認は ⑳（先送り）。

## 1. 仕様（ユーザー依頼）

- スキルのストック（使用可能回数）が 2 個以上あるキャラ（魈・クレー・八重神子・ナヴィア・ヴァレサ）の出場ブロックに、**「アクションバー」と「スキルCT」の間**に 1 行を足す。
- その行に、ストック数を表すバーを出す。ストック 0 のときはバーなし。1 以上のときは、その数をバーの中に書き、**同じ数のままの期間がバーの長さ**になる（数が変わるたびに別のバーになる）。

## 2. 分析（問題が生じないか）

| # | 論点 | 結論 |
|---|---|---|
| 1 | ストック数は、データとして取れるか | **取れる**。CT のキュー（`CooldownQueue`。`rotationCalculator.ts` の `checkCooldownViolations`）は、積まれている CT の数 `size` を持つ。ストック = 最大回数 − `size`。変わる時刻は、(a) スキルを使った（`push`・−1）、(b) 先頭の CT が明けた（`advance`・+1。明けた時刻は `endedAt`）、(c) 祭礼の発動・八重神子の爆発（`release`・+1）、(d) 開始位置の短縮（`reduce`）は個数を変えない（明ける時刻だけ動く）。(a)(c) は呼び出し側が時刻を知っている。(b) は `advance` の中なので、**キューに「明けた」コールバックを足す**必要がある |
| 2 | 数が変わる時刻は、CT バーと食い違わないか | 食い違わない。CT バーも同じキューの先頭から作るので、バーの終わり = ストックが +1 になる時刻。使った時刻（−1）は、CT の開始位置（`ctOffset` 後）ではなく**使った時刻**にする（使った瞬間に 1 回分減る。CT バーは少し遅れて始まる） |
| 3 | 最初のストック | 出場前の状態は不明なので、**満タンから始まる**と仮定する（CT バーも、最初は CT 無しの仮定）。満タン（例: 八重神子 3）の期間が、時間軸の左端から最初の使用まで長いバーになる。**推奨: 満タンのバーは、そのキャラの最初の出場の開始から**出す（出場前の期間は出さない）。ストック 0 は出さない |
| 4 | 時間軸の外の持ち越し（ループ） | CT バーは、2 周目（cycle 1）の発動を使って、折り返しの前から持ち越した CT を点線で出している。ストックも同じ計算（2 周分のキュー）から出せる。1 周目の先頭では、前の周から持ち越した CT 分だけストックが少ない。**1 周目のバーは、キューの 2 周目の動き（cycle 1 の時刻 − ループの長さ）から作り直す**。CT バーの持ち越し（`isCarryOver`）と同じやり方で、点線で出す |
| 5 | CT 違反（ストック 0 で使った） | ストックは 0 未満にならないよう 0 で止める。違反の警告は既存のまま（バーは出さない = 0） |
| 6 | 八重神子の爆発の解放・祭礼の解放 | キューの `release` で size が減る → ストック +1。同じ時刻に使用 −1 と重なっても、時刻順に処理するので、数が変わるたびに別のバーになる。長さ 0 のバーは出さない（CT バーの既存の扱いと同じ） |
| 7 | ヴァレサの無料のスキル（猛烈パッション中の最初のスキル） | キューに積まない（`continue`）ので、ストックも変わらない。正しい |
| 8 | ファルカ・オデット・フリンズの特殊スキル | **別の仕組み**（受付の間だけ使える特殊スキル。`startsAll` / `windowOnly`。受付の外では使えない）。ストックの意味が「受付の間の残り回数」になり、受付の外は 0 扱いが要る。**今回の対象外**（通常のスキルで回数が複数のキャラだけ）。必要なら別途 |
| 9 | 凸で回数が変わるキャラ | マスターの `charges` は固定値。凸で回数が変わるキャラがあるかは、実装の前にマスター・gcsim で確認する（あれば、`charges` の凸の補正を先に入れる） |
| 10 | gcsim の結果の反映 | 反映は CT の長さ（アクションの `cooldown`）を書き換える。ストックは同じキューから出るので、**反映後も CT バーと整合する**（別に持たない。D86 の「同じ仕組みを 2 か所に持たない」と同じ） |
| 11 | 画面の高さ・行の揃え | 左のラベル列と右のバーの領域は、同じ行の並びで作っている（`GanttChart.tsx` 約 1340 行のラベル、約 1600 行のバー）。**両方に同じ条件で 1 行（h-6）を足す**。ストックのバーがあるキャラだけ出す（スキル CT の行と同じ出し方）。他のキャラの行の高さは変わらない |
| 12 | 同じ数が続く場合 | 使った時刻と、別の CT が明けた時刻が同じ（誤差内）だと、数が変わらない。**同じ数が連続するバーは 1 本にまとめる** |
| 13 | 出場ごとのブロック | 出場（stint）ごとのブロックに、同じ行を出す（CT バーの行と同じ。全時間軸に対するバー） |
| 14 | 壊れるもの | 計算結果に `stockSpans` を足すだけ。既存の判定・CT バーは変えない。スナップショット（`check:snapshots`）は、**複数回のキャラの並びに `stockSpans` が増える差だけ**（それ以外の項目は変わらないはず。差を説明してから保存） |

**結論: 問題なし。実装できる。** 確認したい点は 3 つ（§5）。

## 3. 実装計画

### 段階 A: 計算（`rotationCalculator.ts`・`cooldownQueue.ts`）

| # | 内容 |
|---|---|
| A1 | `CooldownQueue` に、先頭が明けたときに呼ぶコールバック（`onExpire(t)`）を足す（`advance` 内。`release`・`push` は呼び出し側で記録する） |
| A2 | `checkCooldownViolations` で、回数が 2 以上の通常のスキルの枠（`キャラ:skill`。`charges > 1`）ごとに、**(時刻, ストック)の変化の列**を記録する（使用 −1・明けた +1・解放 +1。2 周分） |
| A3 | 変化の列から、**同じ数が続く区間**に直して、`StockSpan`（`characterId`・`startTime`・`endTime`・`count`・`isCarryOver?`）を作る。0 の区間は捨てる。1 周目の先頭は、2 周目の動きを使って持ち越し分を反映（点線）。満タンの区間は、キャラの最初の出場開始から |
| A4 | `CalculatedRotation.stockSpans` として出力。`genshin.ts` に `StockSpan` を追加 |

| B2 | バーの領域: 同じ位置に、区間ごとのバー（数字入り）を描く。持ち越しは点線。ツールチップ: 「スキルのストック N 個 [開始 ~ 終了]」。クリックで開始位置へシーク（CT バーと同じ） |

- スナップショットに `stockSpans`（空でないときだけ）を足し、差を説明してから保存。クレー・八重神子（E ×3 → 爆発で解放）・魈・ヴァレサ（無料のスキル）・祭礼つきクレーの並びを追加。
- 内蔵ブラウザで、八重神子（画像の編成）を確認: E ×3 で 3→2→1→0（バー無し）→ CT 明けで 1。爆発の解放で +1。

## 4. 注意点

- ストックは、出場していない間も増える（CT は進む）。出場の外の期間のバーも出る（CT バーと同じ）。
- 満タンの長いバーが目立つ。目立ちすぎる場合は、「満タンのバーは出さない」という選択もできる（§5-1）。

## 5. 確認したいこと（実装の前に）

1. **満タンの期間のバーを出すか**: 推奨 = 出す（最初の出場の開始から）。仕様の「1 以上は出す」に従う。
2. **ファルカ・オデット・フリンズの特殊スキル**は対象外でよいか（受付の間だけ使える仕組みで、別の定義が要る）。推奨 = 今回は対象外。
3. **持ち越し（ループの折り返し）のストック**を、点線のバーで出してよいか。推奨 = 出す（CT バーと同じ）。
