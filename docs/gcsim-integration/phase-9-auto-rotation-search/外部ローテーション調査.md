# 公開されているローテーションの調査（2026-11-22）

## KQM Sim Database の中身（取得して集計。2026-11-22）

- 6,025 件。うち 5,817 件が `for` ループの形（1 周ぶんのローテーションを繰り返す）。ほぼ全件に説明文がある（例: 「19s rotation. 4[C] + ( Q / C_4b ) depending on Q ready.」）。
- 1 件の中身: 編成 4 人・装備・聖遺物・凸・`active <先頭>`・ループ内の `<キャラ> 行動, 行動, …;`。分岐は `if .<キャラ>.burst.ready { … } else { … }` や `while .<キャラ>.nightsoul.points > 8 { … }`。
- 出現数の多い順: フリーナ 1,786・ベネット 1,750・フィッシュル 1,367・ナヒーダ 949・夜蘭 919・万葉 747。少ないキャラ: イファ 7・フリンズ 34・ヴァルカ 9・ダリア 20 など。
- マスターの gcsim 対応キャラとほぼ一致（DB にあるが、マスターにないキャラは 0）。DB に 0 件の対応済みキャラ: 空(氷)・イアンサ・兹白・イルーガ・サンドローネ・アリョーシャ（キー名の違いの可能性。要確認）。gcsim 未対応の 8 人は、DB にもない。

## 辞書に使える点・できない点

使える:
- キャラごとの「実際に使われている形」を、件数と DPS つきで集計できる（例: 魈 `skill:2, burst` + `jump, high_plunge` の繰り返し、イファ `attack, skill` のあと、ナイトソウルが多い間 `charge` を連打して `burst`）。
- 行動の名前が、辞書の行動 ID と素直に対応する: attack→n・charge→ca・skill→e・`skill[hold=1]`→e_hold・burst→q・dash・jump・high_plunge→hp・low_plunge→lp。
- 現在の Wiki 由来の形が当たっていないキャラ（イファ −34%・リネ・荒瀧一斗・申鶴・ニコ）の、裏付けや修正の材料になる。

注意:
- **辞書は「1 回の出場 + 繰り返し」**の形しか持てない。KQM の設定は、1 周の中で同じキャラが何度も出る（例: ドゥリンの `skill, burst, skill` → 次の周は `skill:2, burst`）。そのまま辞書にはならない。**キャラごとに「最も多い出場 1 回ぶん」を取り出す**加工が要る。
- 分岐（`if .burst.ready` など）や、ナイトソウル・粒子による条件は、辞書の形に写せない。分岐の片方（主に burst が使えるとき）を選ぶ。
- 装備・凸・聖遺物は、KQM は上級者向けの設定で、このアプリの「仮値」とは違う。同じ行動でも、DPS の数値は比べられない（行動の形だけを使う）。
- 権利: KQM の投稿は利用者が提出したもの。**設定ファイルをそのまま取り込まず、行動の「形」（事実の集計）だけを辞書に使い、出典（件数）を `evidence` に書く**のが安全。API を使うときは、間隔を空ける（今回は 1 秒おき・62 回）。規約・robots.txt に、禁止の記述は見つからなかった。

## 次にやるとすれば

1. `scripts/knowledge-kqm-db.ts`（仮）: DB を取得してキャッシュ（`.cache/`）→ キャラごとに、行動のまとまりを集計し、上位の形を行動 ID に直して一覧表示（`knowledge-wiki-combos.ts` と同じ位置づけの調査道具）。
2. 一覧を見て、辞書にない形・Wiki 由来の形と食い違うものを、1 キャラずつ追加・修正 → 探索で測る（辞書なし・あり）。
3. 取得したデータは、容量（約 31 MB）があるので Git に入れない。

## 道具（作成済み）

`scripts/knowledge-kqm-db.ts`: `--fetch` で DB を `.cache/kqm-db/` に取得 → `node scripts/knowledge-kqm-db.ts イファ 魈` で、キャラごとの出場の形（件数・DPS）・DPS 上位の設定・いまの辞書の形を並べて表示（`--all` は、全キャラを `.cache/kqm-db/<名前>.md` に書く）。条件つきの行動は `?` を付けて示す。
