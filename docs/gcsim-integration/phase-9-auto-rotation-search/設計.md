# ローテーション自動探索の設計（案）

作成: 2026-11-20 / 状態: **案（決める点を 1 つずつ確認中。A・B・C 決定済み）**

関連: [plan.md](plan.md)（構想・決定ログ）、[役割の下書き.md](役割の下書き.md)（役割の表。確定済み）

## 1. 目的と入出力

- **入力**: 編成（持ちキャラ 4 人。装備・凸・天賦は持ちキャラの値）、キャラごとの役割（`effectiveRoles`）、戦闘条件（敵・通常モード/幽境モード）。アクションは、何も設定されていない。
- **出力**: DPS が高い順の、ローテーションの候補（出場の順番・各出場のアクション）。選んだものを、そのままガントチャートに置ける（今のアプリの `Stint[]` の形）。
- **探索ではなく、検算に gcsim を使う**（plan.md の構想）。gcsim は 1 候補ごとに数秒〜かかるので、候補を数十個に絞ってから回す。

## 2. 全体の流れ（4 段）

```
① 骨組みの生成 → ② CT 違反の除去 → ③ 簡易スコアで絞る → ④ gcsim で検算 → 順位表
```

### ① 骨組みの生成（アプリ内。gcsim は使わない）
1 つの「ローテーション」を、次の部品の組み合わせで作る。

| 部品 | 内容 | 選択肢の数（目安） |
|---|---|---|
| 出場の順番 | 役割ごとの置き場所の規則つきの並べ替え（サポーター → サブアタッカー → アタッカーの順を基本にする） | 最大 4! = 24 → 規則で数個 |
| 非アタッカーの出場 | `e` → `q` だけの短い出場（スキル・爆発を使って、すぐ交代） | 1〜2 通り（E を長押しできるキャラは、長押しも） |
| アタッカーの出場 | 単独 DPS の測定で使った型（通常攻撃・通常＋重撃・重撃・落下・長押し E 始まり）＋ 繰り返し回数 | 型 5〜7 × 回数 3〜4 |
| 2 回目の E | アタッカーが出場中に、CT が戻っていれば E をもう 1 回使う | あり / なし |
| 使う E・Q | キャラごとに、E・Q を使うか使わないか（決定 A） | 規則で絞って数十通り |

- アタッカーが 2 人以上のときは、それぞれの出場を作り、順番の並べ替えに入れる。
- サブアタッカーは、**連係攻撃が続くあいだに、アタッカーが表で攻撃する**配置にする（サブアタッカーの `e` / `q` を先に出し、効果時間のうちにアタッカーの出場を重ねる）。
- サブアタッカーの置き方は、決定 B（下）に従う。
- 役割が複数あるキャラは、決定 C（下）に従って、役割の割り当てを候補に入れる。
- 「1 ローテーション」の長さは、下の「1 ローテーションの長さ（決定 A）」で決める。

#### 1 ローテーションの長さ（決定 A。2026-11-20）
- **長さの目安 = 「使う E・Q」のうち、CT が一番長いものの CT + 1 秒ほど**（例: 使う技の最長 CT が 18 秒なら、約 19 秒）。ループしても CT が戻っているようにするため。
- **どの E・Q を使うかも、探索の対象にする**。特定の E・Q を使わないほうが DPS が伸びることがある（CT の長い E を外して、ローテーションを短く回すなど）ので、キャラごとに「E を使う / 使わない」「Q を使う / 使わない」を候補に入れる。外すと、長さの目安（最長 CT）が変わり、ローテーションの長さも変わる。
- 外す組み合わせは、全部は試さない（4 人 × E・Q = 8 個 → 256 通り）。規則で減らす: アタッカー・サブアタッカーの Q は、基本的に使う（外すのは、E だけを外す・長 CT の技を 1〜2 個外す候補まで）。サポーターは、E・Q とも外せる候補を持つ。
- 長さの目安に収まらない分（アタッカーの攻撃が余る・足りない）は、アタッカーの攻撃の回数で合わせる。

#### サブアタッカーの置き方（決定 B。2026-11-20）
- サブアタッカーは、**アタッカーの出場の前に、短い出場（E → Q）で設置物・効果を出して交代**し、その効果が続くあいだに、アタッカーの出場を重ねる。
- 効果時間が短いサブアタッカーは、アタッカーの出場の直前に置く（効果時間の長いものを先に置く）。
- 1 ローテーションに、サブアタッカーの出場は 1 回。「効果が切れたら、同じローテーションの中で再度出場させる」候補は、最初は作らない（あとで足せる）。

#### 役割が複数あるキャラ（決定 C。2026-11-20）
- そのキャラが持つ役割のうち、**どの役割で置くかを「割り当て」として候補に入れ、全部の組み合わせを試す**（例: 雷電将軍がアタッカー ＋ サポーターなら、「雷電将軍がアタッカー・他がサポート」と「雷電将軍がサポート・他がアタッカー」の両方）。
- **アタッカーの割り当てが 1 人もない組み合わせは捨てる**（アタッカーは、最低 1 人必要）。
- 割り当ての数は、最大 2^4 = 16 通り。サポーターとサブアタッカーの両方を持つキャラなどは、割り当てを役割の数だけに絞って、規則で減らす。

### ② CT 違反の除去（既存の部品を使う）
- 候補を `calculateRotation(characters, stints, options)`（`src/utils/rotationCalculator.ts`）に通す。
- 返る `validationIssues`（CT 違反・スタミナ・落下の前提など）が 1 つでもある候補は、捨てる。
- 2 周目の折り返し（ループ）を含めて判定されるので、ループしたときの CT 違反も見つかる。

### ③ 簡易スコアで絞る（アプリ内。速い）
`calculateRotation` の結果（`activeBuffs`・`passiveSpans`・`calculatedStints`）から、次を計算して、上位 N 個（既定 30 個）に絞る。

- **アタッカーの表の時間**: ループのうち、アタッカーが場にいる時間の割合。
- **重なり**: アタッカーの表の時間と重なっている、バフ・デバフ（発動バフ・武器・聖遺物・天賦の効果）の秒数。
- **サブアタッカーの稼働**: サブアタッカーの効果（設置物など）が、ループの何割で続いているか。
- スコア = 上の項目の重みつきの和（初期値は手で決め、gcsim の結果との相関を見て直す）。

簡易スコアは、**正しさではなく足切り**に使う。上位 N に入れるのが目的。

### ④ gcsim で検算（WASM）
- 上位 N 個を、`buildGcsimConfig` → `dpsCalc.computeDps`（実行回数は既定の少なめ。例: 10 回）で回す。DPS の高い順に並べる。
- 上位数個だけ、実行回数を増やして、順位を確かめる（任意）。
- 実行は、既存の Web Worker 経由（`gcsimWasm.ts`）。進行状況（何個目か）とキャンセルを出す。

## 3. 部品の再利用

| 部品 | 使う場所 |
|---|---|
| `calculateRotation`（`rotationCalculator.ts`・`rotation/cooldownCheck.ts`） | ② CT 違反の除去・③ のスコアの材料 |
| `buildGcsimConfig` / `dpsCalc.computeDps` / `runGcsimSample` | ④ 検算 |
| `scripts/solo-dps.ts` の型の一覧（`TEMPLATES`） | ① アタッカーの型（アプリ内の部品に移す） |
| `effectiveRoles`（`characterRoleStore.ts`） | ① 役割の判定 |
| 持ちキャラの装備（`ownedToPartyFields`・`ownedStore`） | 編成のキャラの装備 |

## 4. 画面（案）

- 編成の画面に、「ローテーションを自動探索」のボタン（アクションが空のときに押せる）。
- 押すと、進行状況 → 順位表（DPS・出場の順番・各出場の要約）。1 つ選ぶと、ガントチャートに置ける。
- 探索の設定（候補の数、実行回数、戦闘時間）は、折りたたみにする。

## 5. 検査

- 生成した候補が、全て `calculateRotation` で違反ゼロになること。
- 既知の編成（ガイドや既存の保存データにある、評判のよいローテーション）を入力にして、探索の結果が、それと同じくらい（例: 90% 以上）の DPS を出すこと。
- 簡易スコアの順位と gcsim の DPS の順位の相関（上位 N に、gcsim 最良の候補が入っているか）。

## 7. 既知の制約

- アプリの時間計算は、爆発のエネルギー不足を見ない（アプリの通常の計算と同じ）。探索の結果は、元素チャージ効率が足りない編成では、実際のゲームで回らないことがある（フェーズ 7 の必要元素チャージ効率で別に確認する）。
- gcsim の結果は、実行ごとに揺れる（ダメージの乱数・粒子）。実行回数が少ないと、近い順位は入れ替わる。
