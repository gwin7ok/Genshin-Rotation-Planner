■ 運用ルール（前のセッションと同じ）
- アプリは未リリース。旧データの残存は考慮しない。画面の確認は、マスターデータを全件削除→再生成→登録した状態で行う前提（DB バージョンは 33）。
- 実装方法に選択肢があるときは、メリット・デメリット・推奨を示し、選択肢は本文に番号つきで書いて、私に選ばせる。確認を頼むときは、具体的なキャラ・アクション名を指定する。説明は具体例つきで。
- コミットは私が行う（**現在の変更はすべて未コミット**）。返答は日本語。
- 用語: 複数回分のスキルの説明で「チャージ」は使わない（爆発エネルギーと紛らわしい）。「CT・クールタイム・使用可能回数」と書く。
- 編集の注意: 正規表現・バックスラッシュ・バッククォートを含む置換は、Bash のヒアドキュメントや sed で壊れやすい。Edit / Write ツール、または Write で作った一時スクリプト（`$TEMP` 以下）を使い、編集後は `npx tsc --noEmit`。一時スクリプトは使い終わったら消す。**`src/types/genshin.ts`・`src/masterdata/characterMasterGenerator.ts`・`src/components/StintSequenceEditor.tsx` などは CRLF**（`rotationCalculator.ts`・`GanttChart.tsx` は LF）。複数行の置換は、改行をファイルに合わせる（`String.fromCharCode(10/13)` で扱う）。Node の TypeScript の直接実行（`node x.ts`）は strip-only なので、コンストラクタの引数プロパティ（`constructor(readonly x: number)`）は使えない。
- gcsim のソースは、`gh api repos/genshinsim/gcsim/contents/<path>?ref=1e6c1a8621728dfa8d420a861092259e752c4953`（`gh` はログイン済み）で読める。設定文の実行は、`POST http://localhost:54321/sample/<id>` に `{config, seed:1}` を送り、返る `logs` を見る（スクラッチパッドは、セッションをまたぐと消える）。
- マスターデータと編成のデータは、名前ではなく必ず ID をキーにする（D13）。

■ 前のセッションで完了したこと（概要）
ファルカ（Varka）の特殊スキル（出づる四風）の対応。詳細は phase-6 の progress.md。
- **CT は gcsim のキュー方式が正しい**（動画の観測表で確認。D70）。`CooldownQueue`: 先頭だけが時刻を持ち、先頭が 0 になった時点から次が満額で始まる。短縮は先頭の残りまで（超過分は捨てる）。バーは、判定のキューで CT が始まった時点に作る（`checkCooldownViolations` が `CooldownSpan[]` を返す）。受付（疾風怒濤）の有効な終わりより後に始まる待機中の CT は積まない。
- 受付（疾風怒濤）= 12 秒 + 開始 0.65 秒 + ファルカ自身の爆発 2.3 秒 + ヒットストップ。ヒットストップは**書き戻した所要時間のアクションにだけ足す**（D71。所要時間にも止まった分が含まれるため。両方足す／両方足さない）。受付の外の特殊スキルは、警告（黄色）を出し、特殊スキルの CT を積まない（gcsim では通常スキル）。
- 受付の間の重撃（CA）は、特殊スキルの回数に空きがあれば特殊重撃になって 1 回分を使う（`optional` のイベント）。
- 風元素共鳴（風 2 人）で全 CT × 0.95（`cdResonanceScale`）。書き戻した CT には `gcsimCdResonance` を保存し、共鳴が変わったら比で補正する。
- 敵の防御ヒットストップ（gcsim の `defhalt`）の切り替え（出場編集の画面。既定 有効。無効なら gcsim に `defhalt=false` を渡す）。
- gcsim の実行結果の表で、特殊スキルの CT が「爆発」と表示されていた不具合の修正。
- 取り下げ: gcsim への「CT が並行して減る」という issue 草稿は誤りなので投稿しない。
