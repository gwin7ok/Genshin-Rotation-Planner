# ローテーション自動探索エンジン 設計原則＆再発防止ガイド

- 対象コード: `src/utils/rotationSearch/*`, `src/utils/gcsim/buildGcsimConfig.ts`, `src/masterdata/knowledge/*`
- 目的: Phase 0〜3 の実測検証で判明した「原神の仕様 × 自動探索アルゴリズムの落とし穴」を設計ルールとして固定し、今後の自律改善ループでリグレッション（先祖返り）を防ぐ。

---

## 1. 評価・順位付け（`search.ts` / `dpsCalc.ts`）の不変ルール

1. **指定周数（`loops`）を必ず渡し、完走失敗（`truncated`）を強ペナルティ化する**
   - 過去の事故: `computeDps` に `loops` を渡さず `truncated` を無視していたため、2周目で 119 秒エネルギー待ちフリーズした国際タルタリヤが「1周目（開始満タン）のダメージ ÷ 20秒」で計算され 1 位を独占した。
   - ルール: `truncated` が発生した候補は `× 0.35 * (worst / loops)` で大きく減点し、指定周数を完走できるローテが必ず勝つようにする。
2. **純粋な `dps.mean` 単一ソートを禁止し、実戦スコア `rankScoreOf` を使う**
   - 考慮項目: `sd`（最終順位で `dps - 0.35 * sd`）、`energyWaits`（1周あたり待ち0.3s超過分に減点）、`ctIssues`（`0.97 ** ctIssues`）、および微小な複雑度コスト（オッカムの剃刀）。
3. **最終検証直前に「クリーンアップパス（オッカムの剃刀）」を必ず挟む**
   - 上位候補から「末尾の `dash`/`jump` 削減版」「不要なサポーター `n` 削減版」「不要な単独 `n` 初動削減版」を生成して `runs2` で直接対決させる。
   - 実戦テクニック（フリーナ `E D`・香菱 `Q E D`・万葉 `N tE`）は実際に DPS が上回るため自動的に生き残り、+0.2% 程度のゴミ手だけが綺麗に消える。

---

## 2. 簡易スコア（`evaluate.ts`）とシード展開（`knowledgeSeeds.ts`）の不変ルール

1. **`attackerFraction` への線形比例を禁止（逆相関の防止）**
   - 過去の事故: `attackerFraction * (1 + 0.25 * overlapPerSecond)` は「サポート放置でアタッカーが殴り続ける形」を最高点にし、7編成中5編成で負の相関（`-0.10`〜`-0.41`）を起こした。
   - ルール: チーム全体のスキル・爆発参加率と適正表時間帯（0.30〜0.65）・適正周期（14〜24s）を掛け合わせる。
2. **知識シードの優先順位を簡易スコアで壊さない**
   - `knowledgeSeeds` のラウンドロビン順（各キャラ `o[0]` 基準が先頭）を尊重し、`keep1` の最大 65% をシード優先枠、残りを総当たり枠に配分する。
3. **全員非アタッカー編成のフォールバックを消さない**
   - 過去の事故: `furina-vaporize`（全員 `supporter`/`subAttacker`）で `if (attackers.length === 0) return [];` によりシード 0 件となり `84.4k → 70.8k` に激減した。
   - ルール: `attackers.length === 0` のときは `slot` 最大キャラを暫定アタッカー扱いしてシードを組む。
4. **専任アタッカーがいる編成では、兼任キャラ（`attacker+supporter`）の `supporter` 型を優先する**
   - 例: 刻晴激化でナヒーダの `attacker` 型がシード枠を食い潰すのを防ぐ。
5. **同 `slot` 帯でのサポート順序入れ替え（例：万葉↔ベネット）が生成される `slot` 設計を守る**
   - 雷電ハイパーでは `ベネット(slot 10)` と `万葉(slot 10)` が同じ `slot` 帯にあることで `万葉→ベネット→裟羅`（42.7k）が生成される。

## 3. 近傍生成（`candidates.ts`）とゲーム仕様ガードの不変ルール

1. **サポーターの通常攻撃 `N` は 3 段階で厳密に区別する**
   - **① 自由許可（`canSupporterUseFreeNormal`）**: 西風武器装備、または固有ギミック必須（シロネン `E N×2`、ニィロウ `E N×2 E`）。
   - **② 追撃トリガー用 1 手のみ許可（`canSupporterUseTriggerNormal`）**: 編成に通常連動追撃キャラ（6凸フィッシュル・行秋・夜蘭・北斗・トーマ）がいるとき、**`e`/`e_hold`/`q` を含む Stint 内に 1 回だけ `n` を許可（ペナルティ 0）**。目的はナヒーダ 1.5U 草下地の上からオズ追撃→万葉 `N tE` で雷拡散を通すこと。**同一 Stint 内の `N×2`・`CA` 置換や単独 `N` 初動は禁止**。
   - **③ それ以外**: 6凸ベネットの炎付与が編成にあっても、控えサポーターへの `N` 挿入は禁止。
2. **Early Priming（早期反応起動：`newE` / 法器 `newN` / `lead`）を保護する**
   - 月開花（草露の獲得時間制限）や星電導（極星フィールドの立ち上がり）では、ローテ最序盤の初回反応起動が極めて重要。
   - `loop === 0` の候補に対し、短 CT（≤12s）または長持続（≥18s）スキルを先頭配置する `newE`（例：`サンドローネ[E] → ↻八重神子[E×3]`）を必ず残す。
   - 法器の単独 `N` 初動（`newN`）は、水・草・氷・雷の法器かつ直後が別元素で即反応できる並び（例：`コロンビーナ[N] → 草`）のみ許可（-0.2%微調整のみ）。
3. **キャラ固有の gcsim 変換ルール**
   - **タルタリヤ（`tartaglia`）**: 交代時に弓モードへリセット、`e` 毎に `inMelee` をトグルし、双剣中の `ca` は `charge`（直前 `n` 必須）、弓中の `ca` は `aim` を出力する。

## 4. 知識辞書（`src/masterdata/knowledge/characters.ts`）の品質基準（CI ガードレール）

1. **1 キャラあたり精鋭 2〜4 件**（肥大化 6 件以上は組み合わせ爆発で探索精度を落とすため禁止）。
2. **`archetypes[0]`（先頭）は必ず無凸・主ロールの汎用定番形**（`bad-first-entry: 0`）。
3. **1 出場 10 手以上のべた書き禁止**（必ず `fill`＋`fillCount`＋`lead`/`tail` で構造化、`excessive-length: 0`）。
4. **3 回以上出場（`then.length >= 2`）は原則禁止**（ヌヴィレットの雫4重撃など明確な固有リソース収支の例外のみ）。
5. **星4キャラの凸制限（`constellation.min`）は、実際にアクション構造が変わる例外のみ**（ファルザン6凸単体Q・シュヴルーズ4凸3連E・藍硯6凸E×2・凝光2凸/6凸・ドリー6凸等）。KQMの6凸偏りによる機械付与は厳禁。
6. **`--apply` 等の自動編集は括弧深度トラッキングで行い、文字列 `indexOf` は使用禁止**（`wrong-character: 0`, `inline-closing-bug-risk: 0`）。
