# HoYoLAB 取り込み アプリ側の設計（案）

状態: **案（決めたい点あり）**。2026-11-17。前提・調査結果は [plan.md](plan.md)。

## 目的と範囲
- 取り込んだ持ちキャラの装備・ステータスを、編成のキャラに反映し、gcsim の設定文（キャラ・武器・聖遺物・ステータス）に出す。
- **範囲外（別の機能）**: 現在のアプリは、gcsim の結果から**時間（ガントチャート）だけ**を読む。ダメージの数値は読んでいない。ダメージの表示は、本機能が入ったあとの別の作業にする（本機能は、そのための「正しいステータスを gcsim に渡す」土台）。

## データの持ち方（推奨）
1. **持ちキャラの保存**: 変換済みの `OwnedCharacter[]` を、`SETTING_KEYS.ownedCharacters`（JSON）に保存する。`persistence.ts` 経由なので、バックアップに自動で入る。生の HoYoLAB の JSON（約 2MB）は保存しない（UID・所持品が入るうえ大きい）。保存する分は 1 キャラ約 1KB、全 92 体で約 90KB。
2. **編成への反映は「コピー（スナップショット）」**: 編成の枠（`PartyMember`）に `build?: OwnedBuild`（レベル・突破・天賦・武器レベル・聖遺物のセット数とステータス・旅人のパラメータ）をコピーして持たせる。
   - 理由: 保存編成・共有 URL・バックアップが、持ちキャラの保存と切り離されて再現できる（他の人の持ちキャラが無くても開ける）。取り込みを更新しても、保存済みの編成の数字が勝手に変わらない。
   - 既存の項目（`constellation`・`weaponId`・`weaponRefinementRank`・`artifactSetId`・`artifactSetMode`）は、コピー時に持ちキャラの値で更新する。**同じ値を 2 か所に持たない**ため、`build` にはこれらを重複して持たせない（`build` は、既存項目にない分だけ）。
   - 4 個セット → `artifactSetMode: '4pc'`。2+2 などの組み合わせ → `'2+2'`（既存の意味は「発動バフなし」のまま）で、聖遺物の `add set` は `build` 側のセット数から出す。
3. **設定文の生成**（`buildGcsimConfig.ts`）: `build` があるキャラは、`lvl=` / `talent=` / 武器 `lvl=` / `add stats` を `build` から出す。無いキャラは、従来の仮値（Lv90/90・天賦 9,9,9・会心率 100%）のまま。
   - 変換は、すでにある `buildOwnedCharacterLines`（[importCharacters.ts](../../src/utils/hoyolab/importCharacters.ts)）を使う。

## 決めたい点（要確認）
| # | 内容 | 推奨 |
|---|---|---|
| 1 | 編成への反映を、コピー（推奨）にするか、持ちキャラへの参照にするか | コピー |
| 2 | **必要チャージ効率の計算**（フェーズ 7）との関係。持ちキャラのステータスには、聖遺物のチャージ効率が含まれる。計算が足す `er=` の扱い（「聖遺物の分を引いた上乗せ」にするか、持ちキャラ使用時は計算の対象外にするか） | 持ちキャラ使用時は「現在の ER で足りるか」を表示し、必要値の算出は従来どおり仮値の編成で行う |
| 3 | 旅人のストーリー強化（真月など）の指定。達成状況は取れない | 取り込み時に、真月なしを既定にし、持ちキャラの画面で切り替えられるようにする |
| 4 | 突破段階が不明なキャラ（境界のレベル）の決め方 | 取り込み時に gcsim で両方を試し、基礎 HP が合う方を採る（イファで確認済み） |
| 5 | gcsim 未実装・マスターにない持ちキャラ（ドール男女・新キャラ・初期武器など）の扱い | 一覧には出し、「編成に入れられない」理由を表示する |

## 画面
1. **持ちキャラの取り込み**（新しい画面。ヘッダーのボタンから）:
   - 拡張機能の検知（`ping`）。無ければ、導入手順（リリースの zip）を表示。
   - UID を入力して取り込む（UID は端末に保存する設定に。入力の手間を減らすため）。
   - 取り込み結果の件数・注意（突破段階・マスターに無いもの）を表示。
2. **持ちキャラの一覧**（同じ画面の中）: 元素・武器種で絞り込み。各キャラに、Lv・凸・武器・聖遺物セットの要約を出す。
3. **編成の設定画面**（`PartyConfigModal`）: キャラを選ぶと、持ちキャラがあれば「持ちキャラの装備を使う」を出す。オンにすると、武器・聖遺物・凸を持ちキャラの値にし、`build` をコピーする。要約と、「使わない（仮値に戻す）」ボタンを出す。旅人は、真月などの切り替えを出す。
4. 文言は ja / en の両方（`npm run check:i18n`）。

## 拡張機能との連携
- アプリ → `window.postMessage({ source: 'grp-app', type: 'ping' | 'hoyolab-fetch', uid, requestId })`。拡張機能 → `{ source: 'grp-ext', ... }`（[content.js](../../extension/hoyolab-importer/content.js)）。
- 応答は、生の JSON（約 2MB）。アプリは、受け取ったら変換して `OwnedCharacter[]` だけを保存し、生の JSON は捨てる。

## 配布・公開まわり
- リリースの zip: `extension/hoyolab-importer` を zip にして、GitHub のリリースに添付する（`release.yml` の変更が要る。`npm run extension:pack` を作る）。
- `docs/privacy.md`: HoYoLAB のデータは、利用者のブラウザの中だけで扱い、外部に送らないことを追記する。
- 公開サイトの拡張機能の導入手順ページ（リリースページへのリンクと、デベロッパーモードの手順）。

## 実装の順序（案）
1. 型と保存（`OwnedCharacter` の保存・読込・バックアップの検査）。
2. 設定文の生成に `build` を反映（`check:` スクリプトで、設定文の往復を確認）。
3. 取り込み画面（拡張機能の検知・取得・一覧）。
4. 編成の設定画面の「持ちキャラの装備を使う」。
5. 拡張機能の zip 化・リリース・文書・i18n。
