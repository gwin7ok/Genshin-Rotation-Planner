# HoYoLAB 持ちキャラ取り込み 計画・調査結果

HoYoLAB の戦績（全キャラクター）から、所持キャラの詳細（レベル・凸・天賦・武器・聖遺物・ステータス）を取り込み、
編成に入れたキャラの gcsim 用ステータスを自動設定する機能の計画。状態: **進行中（調査・試作の段階）**

## 決定ログ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-11-17 | 取得手段は **Chrome 拡張機能**（アプリのボタン → 拡張機能が取得 → JSON をアプリへ返す）。配布は **GitHub のリリースに置いた zip を、利用者が手動で導入**する形から始める | Chrome はウェブストア以外からの自動インストールを禁止している。ストア公開は、動作確認後に再検討 |
| 2026-11-17 | Python の exe（genshin.py 同梱）方式は採用しない | Chrome の Cookie が外部プログラムから復号できない（app-bound encryption）。Python の導入・LGPL（browser-cookie3）の負担もある |

## 調査結果（実機で確認済み）

- **API**: `POST https://sg-public-api.hoyolab.com/event/game_record/genshin/api/character/list` と `character/detail`
  （本文 `{role_id, server, character_ids}`）。出どころは genshin.py（MIT）の実装。
- **認証**: ブラウザのログイン Cookie（`ltuid_v2` / `ltoken_v2`）が自動で付く。ページ上のスクリプトなら、Cookie の値を読まずに呼べる。
  署名ヘッダー `ds` は `md5("salt=<定数>&t=<時刻>&r=<乱数6文字>")` を `t,r,hash` にしたもの。
  追加ヘッダー: `x-rpc-app_version: 1.5.0` / `x-rpc-client_type: 5` / `x-rpc-language: ja-jp`。
- **試作**: [tools/hoyolab-fetch/console_fetch.js](../../tools/hoyolab-fetch/console_fetch.js)（コンソール貼り付け方式）で、
  `act.hoyolab.com` のページから 92 キャラ全員を取得できた。Python（genshin.py）の結果と**完全一致**。
- **取れる項目**: キャラ ID・レベル・凸・好感度 / 武器（ID・レベル・精錬・突破） / 聖遺物（セット名・部位・メイン・サブ・強化回数）
  / 天賦レベル / 合計ステータス（基礎・加算・最終）。

## 変換時の注意（未実装）

1. **天賦レベルは凸の加算込み**（刻晴 C6: 10/13/13）。gcsim には基礎レベルを渡す。凸の説明文の「スキルLv.+3」から、どの天賦が加算されたかを判定する。
2. **キャラの突破段階は取れない**。レベル 81 以上は最大突破。20・40・50・60・70・80 ちょうどのキャラだけ曖昧（今回のデータでは 2 キャラ程度）。
3. **ID の対応**: キャラ ID はマスターの `<id>-<元素>` の `<id>` 部分と一致（90/92。ドール男女は要対応表）。武器 ID は 77/78 一致（初期武器「新米の長槍」のみ不一致）。
   聖遺物セットは HoYoLAB の ID 形式が違うため、**セット名で対応**（33/33 一致）。
4. 聖遺物を付けていないキャラがいる（空として扱う）。旅人は 1 体（氷元素）のみ返る。
5. 合計ステータスから gcsim に渡す値を作る際は、キャラの基礎ステータスを gcsim が持つ点に注意（最終値から基礎値を引く検証が必要）。

## 変換の実装と検証（2026-11-17）

- 実装: [src/utils/hoyolab/importCharacters.ts](../../src/utils/hoyolab/importCharacters.ts)（HoYoLAB の JSON → 持ちキャラ → gcsim の `char` / `add weapon` / `add set` / `add stats` の行）。
  - 天賦: 有効な凸の「スキルLv.+3」の文と、天賦名の一致（中点「・」「·」をそろえる）で、基礎レベルに戻す。並びは [通常, スキル, (ダッシュ系), 爆発]。セトスは凸 3 で通常攻撃が +3 になる（名前の一致で拾える）。
  - 突破段階: レベルから決める。20・40・50・60・70・80 ちょうどは突破前とし、`ambiguousAscension` を立てる（イファ Lv.80 は、実際は突破後 80/90 だった）。
  - 聖遺物ステータス: メイン・サブの値を足す（キャラ・武器の基礎値は gcsim が持つので、最終値からの引き算は不要）。聖遺物セットは名前で対応し、2 個以上のセットを `count=2` / `count=4` で出す。
- 検証: `npm run check:hoyolab-import`（gcsim サーバーが要る）。gcsim の `/sample` が返す `snapshot` の最終ステータスを、HoYoLAB の画面の最終値と比べる。
  - 実データ 92 キャラ中、対象 87 キャラ（gcsim 未実装・マスターに無いものを除く）のうち **74 キャラが一致**、残りは下の理由で説明できる。
  - 説明できる差: gcsim が武器・天賦の効果（護摩の杖・磐岩結緑・鐘の剣・超越の鍵など）を開始時に足す（HoYoLAB の画面には出ない）。イファは突破段階の不明（Lv.80）。熟知は表示の丸めの誤差。
  - 未解決の差: 旅人の武器「星鋒の剣」（gcsim の `exaiphanesblade`）で会心ダメ・熟知が大きく違う（gcsim 側のデータか、マスターの対応の確認が要る）。サンドローネ・シトラリ・ディオナなどの HP・熟知の差は、武器・天賦の効果か要確認。
  - 対応できない: ドール（男・女）はマスターに ID の対応が無い。武器「新米の長槍」（初期武器）はマスターに無い。
- 突き合わせの前提: gcsim の snapshot の並びは、2=防御 3=HP 5=攻撃 7=ER 8=熟知 9=会心率 10=会心ダメ 11=治療 12〜18=炎水氷雷風岩草。

### 差の調査結果（2026-11-17）

調査用: `node scripts/probe-hoyolab-diff.ts <キャラ名>...`（聖遺物セット・武器・キャラのみに分けて gcsim を実行し、差の出どころを分ける）。

- **差の正体は、gcsim が開始時に足す武器・キャラの効果**（HoYoLAB の画面の値には含まれない）。数値で裏が取れたもの:
  胡桃 護摩の杖（ATK +HP の 0.8%＝288）・神里綾人 磐岩結緑（ATK +HP の 1.2%＝261）・ディシア 鐘の剣（HP +基礎 HP の 20%＝3139）・藍硯 彷徨える星（ATK +熟知の 24%＝69）。
  ほかに、ロサリア（死闘の槍）・北斗・八重神子・サンドローネ（超越の鍵）は武器の効果、ディオナ・シトラリは gcsim がキャラ自身の効果（天賦・凸）で HP・熟知を足す（聖遺物セットを外しても、武器を外しても差が残る）。
  → 取り込んだ値（聖遺物ステータス）は正しく、gcsim の計算が、実戦に近い最終値を出していると見てよい。HoYoLAB の画面の値は「武器・天賦の戦闘中の効果を含まない」素の値。
- **突破段階の不明は、基礎 HP で決められる**: イファ Lv.80 は、突破後（80/90）で HoYoLAB の基礎 HP（9383）と gcsim の基礎 HP（9382.9）が一致、突破前（80/80）は 8934 で不一致。
  → `OwnedCharacter.hoyolabBaseHp` を持たせた。アプリで取り込むとき、不明なキャラだけ、両方を gcsim で試して基礎 HP が合う方を採る。
- **旅人: 原因が分かった**。gcsim は、旅人にストーリークエストの強化を足す（既定は全て有効。`+params=[...]` で切り替え）。`base_atk_buff`（+3 攻撃）、`skirk_story_buff`（+7 攻撃・+15 熟知・+50 HP）、`true_moon_story_buff`（会心率 +10%・防御/HP/攻撃 +20%・チャージ効率 +20%・熟知 +60・会心ダメ +20%）。
  この旅人は真月だけ未達成で、`true_moon_story_buff=0` にすると HP 17904（HoYoLAB 17901）・攻撃 2922.7（2922）・防御 719.5（720）・熟知 134（134）・会心率 0.63（63.0%）が一致した。
  → 達成状況は HoYoLAB から取れないので、**真月ありを既定**（gcsim と同じ）にし、編成の設定で凸・諭示のように切り替える（2026-11-17 ユーザー決定。`travelerParams(trueMoon)`）。残る差は、キャラ・武器の効果: 熟知 +160（氷の旅人の固有天賦「熟知 +攻撃の 8%、最大 160」を gcsim が足す。スナップショットを取る時点で値が揺れることがある）、チャージ効率・会心ダメ（武器 星鋒の剣の効果）。

## 配布・導入（決定）

- 拡張機能は `hoyolab.com` への通信許可だけを持つ最小権限にする（`cookies` 権限は使わない）。
- GitHub のリリースに zip を置き、利用者は「デベロッパーモード → パッケージ化されていない拡張機能を読み込む」で導入する。
- アプリは拡張機能の導入有無を検知し、未導入なら導入手順（リリースページへのリンク）を表示する。
