対象の issue: #26（アクション追加の位置制御）・#16（ドラッグ中のリアルタイム表示）・#32（ガントチャート上のアクションの入れ替えがやりにくい。本文なし）。
対象の画面: アクション構築エリア（`StintSequenceEditor.tsx`）・ガントチャート（`GanttChart.tsx`）。選択の状態は `App.tsx` の `selectedAction`（`{ stintId, actionId }`）。

## 1. 現状（コードで確認した動き）

| 項目 | 現状 |
|---|---|
| アクションの追加（`addActionToStint`） | 常に、その出場の**末尾**に追加する。選択中のアクションは見ない |
| 選択 | アクションのクリックで `selectedAction` を設定。解除は `('', '')` だけ（背景クリックでの解除は無い）。出場だけをフォーカスする状態（アクションの選択なし）は持てない |
| アクションの並び替え（ガント） | HTML5 のネイティブドラッグ。ドロップ先は「別のアクションの上」だけで、**その位置の番号に移す**。ドラッグ中は元の位置のまま（結果のプレビューなし）。同じ出場の中だけ |
| アクションの並び替え（構築エリア） | 同じく HTML5 ドラッグ。並べ替えの ◀▶ は D130 で廃止 |

| 交代アクション | 先頭に固定（動かせない・その前に入れられない） |

## 2. 仕様案

### 2-1. アクション追加の位置（#26）

追加ボタンを押した出場カードを S、選択中のアクションを A（出場 X のもの）とする。

| 状態 | 追加の位置 |
|---|---|
| A が S の中にある | **A の直前**に追加 |
| A が別の出場（X ≠ S）にある | S の**末尾** |
| 選択なし（出場だけをフォーカス） | S の末尾 |
| A が交代アクション | 交代の直後（先頭の次） |

- **背景クリック**: アクションの枠の外（出場カードの背景）をクリックすると、その出場をフォーカスしたまま、アクションの選択を外す（`selectedAction = { stintId, actionId: '' }`。`actionId` が空の選択を許す）。
- 追加ボタン・入力欄などのクリックは、背景クリックとして扱わない（選択を外さない）。
- 追加した後の選択: **A のまま変えない**（連続して追加すると、追加した順に A の前へ並ぶ）。
- ガントチャート側には追加の手段は無い（変更なし）。

### 2-2. ドラッグ中のリアルタイム表示（#16）

2 段階で考える。

| 段階 | 内容 | 費用 |
|---|---|---|
| ① 挿入位置の表示 | ドラッグ中に、挿入位置の縦線と「ここに入ります」の表示を出す（出場ブロックには既にある。アクションにも付ける） | 小 |
| ② 結果のプレビュー | ドラッグ中、仮の並びで `calculateRotation` を再計算し、ガントチャート全体（後続の時刻・CT 違反の印・合計時間）を即時に出す。ドロップで確定、Esc・範囲外で取り消し。挿入位置が変わったときだけ再計算する | 中（`App.tsx` に「仮の出場の並び」の状態を足す） |

対象: ガントチャートの出場ブロックとアクションのドラッグ。構築エリアの出場カードは、ドラッグ中に入れ替えが即時に起きる（既にリアルタイム）。

### 2-3. ガントチャート上のアクションの入れ替え（#32）

本文が無いので、コードから、やりにくい原因と思われるものを挙げる。

1. ネイティブドラッグは、ドロップ先が「別のアクションの上」だけで、前後どちらに入るかが分からない。隙間・端には落とせない。
2. 0.2〜0.5 秒のアクションは幅が狭く、掴みにくい・落としにくい。
3. 出場ブロック（マウス方式）とアクション（ネイティブ方式）で、操作感が違う。
4. 同じ出場の中でしか動かせない。

案: アクションも、**出場ブロックと同じマウス方式**に統一する（5px のしきい値・クリックは選択・ポインターの時刻で挿入位置を決める・挿入位置の縦線）。挿入位置は「ポインターの時刻より中点が左にあるアクションの数」（交代アクションの前には入らない）。
