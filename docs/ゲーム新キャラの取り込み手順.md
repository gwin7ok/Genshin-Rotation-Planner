# ゲームに新キャラが実装されたときの取り込み手順

ゲームに新キャラが実装されたとき、アプリ側が「可能な範囲で」そのキャラを使えるようにするための作業の流れ。
gcsim（シミュレーター）の対応は、ゲームの実装より遅れる。**gcsim が未対応の間は、アプリで「編成・アクション構築・ガントチャート」は使えるが、gcsim での計算はできない**（対応表で「gcsim にキャラが未登録」）。
gcsim が対応したら、[gcsim-サーバー更新手順.md](gcsim-サーバー更新手順.md) でバージョンを上げ、下の手順の後半（gcsim 連携）を行う。

個別の技術的な手順（効果継続時間の補完・凸の延長・発動バフの辞書との結び付け）は [新キャラ実装時の作業.md](新キャラ実装時の作業.md) にある。この文書は、それらの全体の流れと順序を示す。

## 段階の全体像

| 段階 | いつ | 何ができるようになるか |
|---|---|---|
| A. アプリだけで使える | genshin-db が新キャラに対応したら | 編成・アクション構築・ガントチャート・CT の計算（gcsim のフレームが無いため、所要時間などは仮の値） |
| B. gcsim のフレームを取り込む | gcsim にキャラが入ったら（gcsim の更新が先） | モーションフレーム・キャンセル・CT開始位置・効果時間の自動計算 |
| C. gcsim で計算する | B のあと | 「gcsim で計算」（実行・結果の書き戻し）。対応表の登録が要る |

## A. genshin-db の対応後（gcsim が未対応でも）

1. マスターを再生成する。
   ```bash
   npm run build:master
   ```
   出力の「gcsim フレームあり」の数と、新キャラが含まれているかを確認する（フレームが無いキャラは、天賦のテキストから作った仮のアクション）。
2. 新キャラが出力に無い・名前が化けるときは、genshin-db 側の未対応・名称の取得を疑う（`scripts/genshin-db-names.ts`）。
3. `src/data/databaseMaster.ts` の `DATABASE_VERSION` を上げる。
4. アプリで、マスターを全件削除 → 再生成 → 登録し、新キャラを編成に入れてアクションを置けることを確認する。
   - アイコン画像は enka.network の URL を使う（`ICON_BASE_URL`）。リンク切れなら、ゲーム内ファイル名の対応を確認する。
5. gcsim のキー（`source.gcsimKey`）が無いキャラは、「gcsim で計算」の実行ボタンが押せない（理由が警告に出る）。これは正しい動作。
6. 記録: 対応表（`npm run check:effectkeys`）で、新キャラのスキル・爆発が「gcsim にキャラが未登録」になっていることを確認する。理由（note）は、キャラごとに `src/masterdata/effectKeyDecisions.ts` の `DEF_DECISIONS` に登録する（`reason: 'not-in-gcsim'`）。

## B. gcsim が新キャラに対応したら

1. gcsim の新しいバージョンを確認する（リリースのノートに新キャラ名）。
2. [gcsim-サーバー更新手順.md](gcsim-サーバー更新手順.md) の 1〜4 を行う（設定ファイルの更新 → サーバーの入れ替え → 辞書とマスターの再生成）。
3. 新キャラのマスターに、モーションフレームと gcsim のキーが入ったことを確認する。
4. [新キャラ実装時の作業.md](新キャラ実装時の作業.md) の手順を行う。
   - 1: 効果継続時間の補完（genshin-db に時間が無い場合）
   - 2: 命ノ星座の効果時間の延長の確認
   - 3: 発動バフと gcsim の辞書の結び付け（新しい武器・聖遺物・固有天賦のキー）
5. 大剣・弓など武器種が新しいキャラは、変換規則（`src/utils/gcsim/actionMapping.ts`・`chargeRules.ts`）が当てはまるかを確認する（重撃の直前に通常攻撃が要るキャラ、長押しの指定など）。
6. 記録（旧「gcsim にキャラが未登録」の決定の削除）: `DEF_DECISIONS` の該当キャラの `not-in-gcsim` を消す。
7. アプリ側だけの対応（issue #36）を使っていたキャラは、`src/masterdata/appSideCharacterSources.ts` の表から、そのキャラの行を消す（リリースの値に置き換わる。PR の値と食い違う点は `progress.md` に記録）。

## C. gcsim 連携の登録（対応表）

1. `npm run probe:effects` → `npm run link:effects`（gcsim を実行。中間データ）→ `npm run link:actions`（マスターのアクション定義に取り込む）を実行する。新キャラのスキル・爆発が、効果のキーに自動で紐づく（または「キー無し」になる）。
2. `npm run coverage:links` を実行して、全体の文書（`docs/gcsim-integration/phase-6-run-and-apply/key-link-coverage.md`）の「未検討」を見る（A: スキル・爆発も B: 固有天賦・命ノ星座・武器・聖遺物も、この 1 つで見られる。決定の置き場は `src/masterdata/keyLinkDecisions.ts` の案内）。決めたら `npm run link:actions` で取り込み、もう一度 `coverage:links` で確認する。新キャラの分は、次のどれかにする。
   - 紐づける: そのまま（自動）、または `actionEffectKeyOverrides.ts`（本体）・`actionEffectExtras.ts`（副次効果）・`actionEffectIncluded.ts`（含まれる効果）
   - 紐づけない: `effectKeyDecisions.ts` に理由つきで登録する。理由の種類: `no-bar`（gcsim の効果なし・バーを出さない）/ `app-bar`（アプリ側の値でバーを表示）/ `decided-not-linked`（gcsim は効果を出すが紐づけず・バーも出さない）/ `not-runnable`（gcsim で実行できない）/ `deferred`（保留。行き先の Step を書く）など
3. 判断のしかたは、単独実行の結果（複数回・組み合わせ）と、gcsim のソース（`internal/characters/<キー>/`）で根拠を確認する。ゲーム内の説明（wiki）と照合が要るものはユーザーに確認する。
4. 画面で通し確認する（gcsim-サーバー更新手順の 7）。

## D. 時間指定のない効果の「全体 / 自分だけ」の確認（追加作業 23 / issue #29）

新キャラ・新しい武器・聖遺物を取り込むと、時間指定のない効果（常時の効果・継続時間のない固有天賦・命ノ星座）が増える。これは、ガントチャートの最下行（全体向け）か、キャラ名の横のバッジ（自分だけ）のどちらかに出る。判定は、説明文の「効果が適用される対象」の部分（`src/utils/buffScope.ts`）で自動に行うが、説明文の書き方によっては外れるので、確認する。

1. `npm run review:buff-scopes` を実行する → `docs/gcsim-integration/phase-6-run-and-apply/buff-scope-review.md` が更新される。
2. 新しく増えた行（新キャラ・新しい武器・聖遺物）の「全体」「自分だけ」の判定を見る。見かたは、**効果が適用される対象が持ち主・装備者なら自分だけ、チーム全員・周囲のキャラ・エリア内のキャラ・状態を持つキャラなら全体**（条件にチームやフィールド上のキャラの語があっても、効果が持ち主に付くなら自分だけ）。
3. 違うものは、`src/masterdata/buffScopeOverrides.ts` に、効果の ID → `'team'` / `'self'` を足す（★上書き の印が付く）。ロジックの判定が外れる書き方が増えたら、`buffScope.ts` の語（TEAM_EFFECT・STATE_HOLDER など）を直す。
4. 画面で確認する（最下行の件数と、キャラ名の横の「✨ 個数」のバッジ）。
