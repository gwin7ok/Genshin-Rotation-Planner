# リリース手順（バージョン管理）

2026-10-12 に決定（D177）。公開先: GitHub Pages（https://gwin7ok.github.io/Genshin-Rotation-Planner/）。

## 版の決め方
- **セマンティックバージョニング**（`主.副.修正`）。出どころは `package.json` の `version`（唯一）。
  - 主: 保存データの互換を壊す変更（バックアップの `version`・保存形式の変更など）、大きな作り直し。
  - 副: 機能の追加（互換あり）。gcsim のバージョンを上げたとき（結果が変わりうる）も、副を上げる。
  - 修正: 不具合の修正・表示の変更・文書。
- タグは `v<版>`（例: `v1.0.0`）。`main` のコミットに付ける。
- 画面のフッターに「バージョン v<版>（コミット <短縮>）」を表示する（ビルド時に埋め込み。`vite.config.ts`・`src/utils/appVersion.ts`）。
- 全データのバックアップには、`app.version`（書き出したときの版）を記録する。
- gcsim の版（`gcsim.config.json`）は、アプリの版とは別に管理する（画面の下部・バックアップに併記）。

## 変更履歴
- `CHANGELOG.md`（日本語。Keep a Changelog 形式。追加・変更・修正・削除・非推奨・セキュリティ）。
- 作業中の変更は `[Unreleased]` に足す。リリースのときに、版と日付の見出しに移す。
- 利用者に見える変更だけを書く（内部の決定 D 番号・計算の内部の変更は、`docs/gcsim-integration/progress.md`）。

## リリースの手順
1. （作業の最後に）`CHANGELOG.md` の `[Unreleased]` を、`[X.Y.Z] - YYYY-MM-DD` に移し、新しい空の `[Unreleased]` を作る。
2. `package.json` の `version` を `X.Y.Z` にする。
3. `npm run check:release`（版と変更履歴の一致・WASM・フォークのタグ・LICENSE）・`npm run check:snapshots`・`npm run check:backup`・`npx tsc --noEmit`。
4. コミット（例: `chore(release): v1.1.0`）→ PR → `main` にマージ。
5. `main` で、タグを付けて push: `git tag v1.1.0 && git push origin v1.1.0`。
   （タグの push では、デプロイは起動しない。github-pages の環境が main のブランチだけを許可するため）
6. Actions の `deploy` を、**Run workflow（ブランチ main）**で実行する。
7. 公開サイトで、フッターの「バージョン v1.1.0」と、「gcsim で計算」の動作を確認する。
8. GitHub の Releases → Draft a new release → タグ `v1.1.0` を選び、`CHANGELOG.md` の該当部分を貼って公開する。

## gcsim のバージョンを上げるとき
`docs/gcsim-サーバー更新手順.md`（6-B: WASM の再ビルドとフォークのタグ `app-wasm-<gcsim の版>`）を行ってから、上のリリースの手順（副を上げる）に進む。

## 注意
- `package.json` の `version` は、`npm version` コマンドではなく、手で変える（コミット・タグの作成は、ユーザーが行う運用のため）。
- 公開した版のタグは、消さない・付け直さない（フォークの `app-wasm-*` タグも同じ）。
