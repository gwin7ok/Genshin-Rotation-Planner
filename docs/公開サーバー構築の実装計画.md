# 公開サーバー構築の実装計画（自宅サーバーでの公開・他の人の自前サーバー）

状態: **計画のみ（2026-09-30 時点で未実装。実装はユーザーの指示を待つ）**
作成: 2026-09-30

## 1. 想定している使い方（ユーザーの説明）

1. **自分・ゲーム仲間向けの公開サーバー**: 自宅 LAN の Ubuntu ノートで稼働させ、ポート開放経由で、ブラウザから利用してもらう。
   - 回線: 同じノートでマイクラのサーバーを外部に公開し、インターネット越しに接続できているので、ポート開放は可能と見ている（CGNAT ではない）。
2. **自前サーバーを立てたい人向け**: GitHub のリモートリポジトリを clone し、環境構築（サーバーの起動・画面のビルド・公開）を自分で行う。

決定（progress.md の決定ログ D61・D62）:
- 公開の方法は **ポート開放（DDNS + リバースプロキシ）**。ポートは 443 のような well-known ではなく、**大きな番号のポート**で公開する。将来は Cloudflare Tunnel（ポート開放なし）に移行する。
- この計画の A〜E は、**現時点では実装しない**（この文書に残す）。

## 2. 全体の構成

```
ブラウザ ──https://<DDNSのドメイン>:<高番号ポート>/──▶ リバースプロキシ（TLS 終端・制限）
                                                      ├ /                → 画面（npm run build の dist/）
                                                      ├ /gcsim/*         → gcsim サーバー（127.0.0.1:54321）
                                                      └ /gcsim-info.json → サーバーのバージョン情報（静的ファイル）
```

- gcsim サーバーは **127.0.0.1 だけ**で待ち受ける（既定）。外に見せるのはリバースプロキシだけ。
- 画面と gcsim を**同じ入口（同一オリジン）**にする。友人のブラウザの `localhost` は友人自身のパソコンを指すため、今の `http://localhost:54321` 直接接続では届かない。
- 利用者のデータ（編成・ローテーション）は、ブラウザのローカルに保存される。サーバーに送るのは、gcsim の設定文（計算の入力）だけ。

### 高番号ポートでの HTTPS（注意）
- 証明書を Let's Encrypt で自動取得する通常の方法（HTTP-01 は 80 番、TLS-ALPN-01 は 443 番）は、高番号ポートだけでは使えない。
- **DNS-01 方式**（DNS にトークンを置いて証明書を取る。inbound のポートが不要）を使う。DuckDNS・Cloudflare DNS など、DDNS/DNS 事業者の API に対応したツール（Caddy の DNS プラグイン、acme.sh、certbot の DNS プラグイン）を選ぶ。
- 利用者は `https://<ドメイン>:<ポート>/` の形で開く（ポート番号を URL に含める）。
- 高番号ポートは、ポートスキャンで見つかる。**目立たなくする効果は小さい**ので、認証・制限・更新は通常どおり行う。
- Cloudflare Tunnel に移行するときは、ポート開放・DNS-01 の手順が不要になる（トンネルが TLS を終端する）。

## 3. 実装項目

### A. アプリの gcsim 接続先を設定で切り替える
- 目的: 公開時に、画面から `/gcsim/`（相対パス）で gcsim を呼べるようにする。
- 内容:
  - `src/utils/gcsim/gcsimConfig.ts` の `GCSIM_SERVER_URL` を、ビルド時の環境変数 `VITE_GCSIM_URL` で上書きできるようにする（未指定は、今の `http://localhost:54321`）。公開用ビルドは `VITE_GCSIM_URL=/gcsim`。
  - `vite.config.ts` に、開発サーバーで `/gcsim` を `http://localhost:54321` へ転送するプロキシを追加（公開と同じ経路で開発・確認できるように）。
  - `gcsimClient.ts` のエラーメッセージ（「公式リリースの server を起動してください」）を、接続先に応じて出し分ける。
  - スクリプト（`probe:effects` など）は、これまでどおり `localhost` を直接使う（設定ファイルのポート）。
- 完了条件: `VITE_GCSIM_URL=/gcsim npm run build` の画面から、プロキシ経由で「gcsim で実行して読み取り結果を見る」が動く。

### B. 公開用のテンプレート一式（`deploy/` に置く）
- `deploy/systemd/gcsim-server.service`: gcsim サーバーの常駐化。専用ユーザー・自動再起動・`-host 127.0.0.1 -timeout 20 -workers 2`・`CPUQuota`/`MemoryMax`・`NoNewPrivileges`。**`-update` は付けない**。
- リバースプロキシの設定（Caddy か nginx。実装時に選ぶ）:
  - 高番号ポートで待ち受け、DNS-01 で証明書を取得・更新。
  - `/` は `dist/`、`/gcsim/` は `127.0.0.1:54321` に転送。
  - **転送してよいパス・メソッドだけ許可**（`POST /gcsim/sample/*`・`POST /gcsim/validate*`。ほかは拒否）。gcsim の CORS は任意のサイトを許可するため、プロキシで `Origin` を自分のドメインに限定する。
  - リクエストの上限（本文サイズ 64KB 程度・同時接続・IP ごとの頻度）、プロキシ側のタイムアウト（20〜30 秒）。
  - 設定文の中身をログに残さない。
  - 選択の目安: nginx は制限（`limit_req`/`limit_conn`）が標準で入っている。Caddy は証明書が簡単だが、頻度制限にプラグインが要る。
- `deploy/ufw.sh`: UFW で、SSH と公開ポートだけ許可（それ以外は拒否）。fail2ban の設定の例。
- `deploy/env.example`: ドメイン・公開ポート・DNS 事業者のトークン（**値は入れない**。`.env` は Git 管理外）。
- 画面のビルドと配置、サービスの再起動をまとめた `deploy/deploy.sh`（`git pull` → `npm ci` → `gcsim:install` → `gcsim:check` → `npm run build` → 配置 → 再起動 → 疎通確認）。
- 完了条件: 新しい Ubuntu に、この一式と手順書だけで、公開まで到達できる。

### C. 「自分のサーバーを立てる手順」の文書（`docs/自分のサーバーを立てる手順.md`）
- 対象: リポジトリを clone して、自分のサーバーを立てたい人。
- 内容: 前提（Ubuntu・Node 22.18 以上〔apt の標準版は古い。NodeSource か nvm〕・git）、clone、`npm ci`、`gcsim:install` / `gcsim:check`、画面のビルド、B のテンプレートの使い方、ルーター（ポート転送）・DDNS・証明書、動作確認、更新の方法（gcsim のバージョンアップは `gcsim-サーバー更新手順.md`）、よくある失敗（CGNAT・ファイアウォール・証明書・ポート違い）。
- AGPL について: gcsim は**改変せず**公式の実行ファイルを使うこと、自分のサーバーの利用者にソースの入手先（このリポジトリ・gcsim のリポジトリ）を示すことを書く。
- 完了条件: 別の人が、文書のとおりに進めて、公開まで到達できる（実際に 1 人に試してもらう）。

### D. サーバーのバージョン確認の仕組み
- 背景: gcsim サーバーには、バージョンや稼働を確認する窓口が無い（`/version`・`/health` は 404）。画面のデータ（辞書・マスター）と、サーバーの gcsim のバージョンが食い違うと、動かないキャラや結果のずれが出る（2026-09-30 に、イルーガで実際に発生）。
- 内容:
  - サーバー側（デプロイ時）に、`gcsim-info.json` を生成して静的に配信する: `{ "gcsimVersion", "gcsimCommit", "appCommit", "builtAt" }`。値は `gcsim.config.json` と実行ファイルの `-version`、`git rev-parse HEAD` から作る（`gcsim:check` に `--write-info` を追加）。
  - アプリは起動時に `/gcsim-info.json` を取得し、ビルド時の `GCSIM_VERSION` と比べる。食い違えば画面に警告を出す（「サーバーの gcsim が古い／新しい。管理者に連絡してください」）。実行ボタンは、警告の上で押せるままにする（判断はユーザー）。
  - `gcsim-info.json` が取れない（ローカルの開発環境など）ときは、何も出さない。
- 完了条件: サーバーの gcsim を意図的に古いバージョンにして、画面に警告が出る。

### E. 画面の表示（非公式表示・出典・ソースの入手先）
- 画面の最下部に、次を表示する: 「非公式のファンツール。ゲームの名称・画像の権利は各権利者に帰属」「gcsim（AGPL-3.0）を使用。ソース: リポジトリ URL」「NOTICE へのリンク」「無保証」。
- 利用規約・プライバシーの短い説明（サーバーに送るのは gcsim の設定文だけ。編成はブラウザのローカルに保存。ログに設定文を残さない）。
- `LICENSE`（AGPL-3.0-or-later の全文）と、各ソースの著作権表示（`NOTICE` は作成済み）。
- 完了条件: 画面から、ソースの入手先・NOTICE・非公式表示にたどれる。

## 5. リスクと対策

| リスク | 対策 |
|---|---|
| 他人の任意の設定文で、CPU を使い切られる | gcsim の `-timeout`/`-workers`、プロキシの頻度・同時接続・本文サイズの制限、systemd の CPU・メモリ上限 |
| gcsim に認証がなく、CORS が任意のサイトを許可している | gcsim は 127.0.0.1 のみ。外に出すのはプロキシだけ。プロキシで `Origin` とパス・メソッドを制限 |
| 自宅の IP が公開される | UFW・fail2ban・OS の自動更新。将来 Cloudflare Tunnel に移行 |
| 証明書の更新失敗で、突然使えなくなる | DNS-01 の自動更新を監視（期限切れの警告メール・ログ確認） |
| ノートの電源・スリープ・回線の停止 | スリープ無効・UPS/ノートの電源設定・systemd の自動起動。停止を許容する運用（友人向け） |
| gcsim のバージョンずれ | D の警告、デプロイの `gcsim:check`、更新手順書 |
| ライセンス | 下の「ライセンス」参照 |
