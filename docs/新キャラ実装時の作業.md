# 新キャラが実装されたときに必要な作業

新しいキャラがゲームに実装され、genshin-db と gcsim が対応したときに、マスターデータ（`characters_master_data.json` など）を更新する手順をまとめる。
項目は、作業のたびに追記していく（現在は「1. 効果継続時間の補完」のみ）。

## 前提: マスターの再生成

新キャラの追加は、まずマスターを再生成して取り込む。

```bash
npm run build:master
```

genshin-db（名前・天賦・CT・効果時間）と gcsim（モーションフレーム）の最新を取得し、キャラごとのアクションを作る。生成後の確認は、マスターを全件削除 → 再生成 → 登録した状態で行う。

## 1. 効果継続時間の補完（スキル・爆発）

### 何が起きるか
スキル・爆発の効果継続時間は、genshin-db の天賦のラベル（例: 「継続時間」「存在時間」）から読み取る。ラベルに時間が無い新キャラ・新しい書き方のラベルは、効果継続時間が空（0）のままになる。効果を持たない技（一瞬で終わる技）も空だが、それは正しい。

### 手順
1. `npm run build:master` を実行し、出力の次の部分を見る。
   - 「効果継続時間の gcsim 補完」: すでに一覧で補っているもの、genshin-db の値との食い違い、アクションが無くなった一覧の項目。
   - 「効果継続時間が空で、gcsim の辞書に時間つきの効果がある候補」: 新キャラのスキル・爆発が出ていれば、補う候補。
2. 候補は、gcsim のソース（`internal/characters/<キー>/skill.go`・`burst.go`）で確かめる。
   - 候補には、命ノ星座（`-c1`〜`-c6`）、内部の猶予（`window`）、複数のキー（例: 印と本体）が混ざる。そのまま採用しない。
   - 「そのスキル・爆発の効果が続く時間」にあたるキーを選ぶ。gcsim の値は、アクションの開始からの時間なので、発動の遅れを含むことがある（例: ジンの爆発 = 10 秒 + 40 フレーム）。
3. genshin-db のラベルが読み取れる書き方（「〜継続時間」「〜存在時間」「〜石化時間」「〜アクティブ時間」）なのに空のときは、手で補うのではなく、`src/masterdata/characterMasterGenerator.ts` の `findAnyDuration` の読み取り規則に、新しいラベルの書き方を足す。
4. 補うときは `src/masterdata/effectDurationOverrides.ts` に、アクション定義 ID・フレーム・根拠（gcsim のキーとファイル）を追記する。
   - キーは `<キャラID>_e` / `<キャラID>_q` など（キャラ ID は「公式キャラID-元素」）。
   - 値は、gcsim のフレーム（60fps）で書く。
5. 再度 `npm run build:master` を実行し、次を確認する。
   - 「補完」の一覧に追加したアクションが出ている。
   - genshin-db に値があるものは、「食い違い」に出ていない（あれば、genshin-db を優先する方針なので、一覧から外す）。
6. マスターデータを変えたので、`src/data/databaseMaster.ts` の `DATABASE_VERSION` を 1 つ上げる。

### 注意
- genshin-db に値があるアクションには、gcsim の値を使わない（genshin-db を優先。決定 D33）。一覧に値があっても、genshin-db に値があれば無視され、食い違いだけがレポートに出る。
- gcsim が未実装のキャラは、gcsim の値を取れない。genshin-db のラベルが読めれば、それを使う。
- 補った値は、アクションの `dataSource.effectDuration` に「gcsim: <根拠>」と記録される。genshin-db の値と区別できる。

## 2. 命ノ星座の効果継続時間の延長の確認

### 何が起きるか
凸の説明文に「〇〇の継続時間+X秒」「〇〇の存在時間+X秒」と書かれているものは、どのアクションの効果が延びるかを人が確認した一覧（`src/masterdata/constellationEffects.ts`）に載せて、初めて反映される。一覧に無いものは、マスター生成のレポートの「凸延長 未確認」に出る。
また、5-3 で効果継続時間を補った（読み取り規則の拡張・`effectDurationOverrides.ts`）キャラは、その効果に対する凸の延長が、新しく「未確認」に出ることがある（例: フィッシュル 6凸「オズの存在時間+2秒」）。

### 手順
1. `npm run build:master` の出力の「凸延長 未確認」を見る。
2. 説明文の延長対象が、マスターのアクションの効果（効果バー）と同じかを、gcsim のソース（`cons.go`）などで確認する。
3. 同じなら `VERIFIED_RULES` に、違うなら理由つきで `NOT_APPLICABLE` に追加する（キーは `<キャラID>_c<凸>`）。1 つの説明文に延長が複数あるときは配列で書く。
4. 再度 `npm run build:master` を実行し、「凸の効果時間延長」の一覧に出ることを確認する。DB バージョンを上げる。

## 3. 発動バフと gcsim の辞書の結び付け

### 何が起きるか
マスターの発動バフ（固有天賦・武器・聖遺物）と、命ノ星座の効果の定義には、gcsim の辞書（`src/data/gcsim_key_catalog.json`）のキーと分類（常時 / gcsim が計算 / 条件付き / gcsim 対象外）が付く。辞書が古いと、新キャラ・新武器・新聖遺物のキーが無く、「gcsim 対象外」になる。

### 手順
1. gcsim が新キャラ・新武器・新聖遺物に対応したら、先に辞書を作り直す。
   ```bash
   npm run build:catalog
   ```
   新キャラの効果の日本語名は、手で補う一覧（`gcsimKeyCatalogOverrides.ts`）で直す。実行で確認するには、gcsim のローカルサーバーを起動して `npm run coverage:catalog` を実行してから、もう一度 `npm run build:catalog` を実行する（実行で出たキーが辞書に合成される）。
2. 辞書を作り直した後に、マスターを再生成する（結び付けは、マスター生成のときに辞書を引いて設定される）。
   ```bash
   npm run build:master
   npm run build:equipment
   ```
3. 出力の「発動バフと gcsim の辞書の結び付け」を見る。
   - 分類ごとの件数（`unsupported` = gcsim 対象外）。新キャラの効果が想定どおりの分類になっているか。
   - 「gcsim の時間で補った固有天賦の効果時間」「命ノ星座の効果の定義を追加」「武器の発動バフの定義を追加」に、新しいものが出ているか。
4. 武器・聖遺物が共有パッケージ（`weapons/common`: 黒岩・金璋君臨・祭礼・西風など）を使う新しい武器のときは、`src/masterdata/buffGcsimLink.ts` の `SHARED_WEAPON_RULES` に、そのキーの接頭辞と対象の武器の条件を追加する。
5. DB バージョンを上げる。

### 注意
- 命ノ星座の効果の定義は、辞書に「時間つきの効果」があるものだけ。永続の効果（常時）は定義にせず、辞書から直接扱う（フェーズ6）。
- 辞書のキーの名前に `a1` / `a4` / `c1`〜`c6` が無い効果は、固有天賦・命ノ星座に対応付けられない（固有天賦は、枠の継続時間が合うものだけ対応付ける）。対応付けられないキャラは「gcsim 対象外」の印になるので、gcsim のソースで実際のキーを確認して、必要なら規則を足す。
